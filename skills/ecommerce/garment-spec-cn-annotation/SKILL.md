# 服装规格书非中文翻译标注 Skill（修正版）

## 本次修正目标

针对上一版出现的两个问题，本版做强约束修正：

1. **禁止乱码**：所有新增批注必须是可正常显示的简体中文；若字体不支持、字符异常、编码异常，必须先修复后再输出。
2. **禁止漏翻/照抄原文**：凡被判定为“需要翻译”的非中文文本，最终成品中必须出现对应的中文译文；不能直接把日文/英文原样作为新增批注贴上去。

如果做不到准确翻译，允许：
- 用更短的中文概括；或
- 标为“待确认”；

但**不允许**把日文片假名/平假名原样当成中文批注输出。

---

## 核心硬规则（必须遵守）

### 1）原图不能重绘

- 原稿作为底图，尽量保持像素不变。
- 只能新增中文批注、少量引线。
- 不得重新生成整张规格书，不得修改表格、线条、数字、日期、款号、版型图。

### 2）新增批注只能是“简体中文为主”

新增批注文本必须满足：
- 主体文字为简体中文。
- 允许少量保留参数、数字、单位、型号，例如 `20mm`、`ACE5030`、`46(M)`。
- 允许括号补充说明，例如 `粘衬（初布化）`。
- **不允许**整条批注主要由日文假名、日文原句、英文原句构成。
- **不允许乱码字符**，如 `�`、异常方框、问号替代字、明显字体缺字现象。

### 3）需要翻译的内容必须翻译

对每个识别到的非中文候选文字，必须先分类：
- `translate`：需要翻译并标注中文。
- `keep`：保留原样，不另加中文，或只做很短中文说明。
- `already_cn`：已有中文，不再处理。
- `uncertain`：确实无法可靠识别时，可跳过或标“待确认”，但要尽量少。

凡归入 `translate` 的项目：
- 最终图上必须出现对应中文。
- 不允许遗漏。
- 不允许用原文直接替代译文。

### 4）批注不能遮挡

- 不覆盖原文字、图线、尺寸、表格线、现有彩色标注。
- 新增批注之间不能互相覆盖。
- 若空间不足：缩短中文、拆两行、换位置、加引线。
- 仍放不下时，可以降低字号，但必须清晰可读。

## 非中文内容的处理标准

### A. 默认需要翻译

以下内容通常应译成中文批注：
- 日文标题、栏位名、部位名。
- 工艺说明、缝制说明、口袋/领/袖/里布/驳头/开衩等结构说明。
- 辅料名称、材料名称、测试注意事项、裁断/接着条件的语义文字。
- 图中衣片名称、衬布位置、口袋布、内外袖、前片后片等说明。

### B. 默认保留原样（不当作漏翻）

以下内容一般保留原图，不需要新增中文或只做补充说明：
- 款号、品番、编号：如 `KHJE6075`。
- 日期：如 `2026/09/10`。
- 数字和单位：如 `130℃`、`12秒`、`20mm`。
- 尺寸规格与号型：如 `46(M)`、`48(L)`、`50(XL)`。
- 型号、胶号、内部代码：如 `ACE5030`、`HBT`、`STT`。
- 品牌英文名：如 `a.v.v HOMME`，可在旁边补充中文 `品牌` 或音译/类别，但不要覆盖原名。
- 人名、公司名、工厂代号等专名。

### C. 缩写处理原则

像 `HBT`、`STT`、`GMP` 这种缩写：
- 原缩写保持不变。
- 若上下文已知含义，可以加中文说明，如 `HBT（防伸带）`。
- 若不确定，不要编造全称。

## 强制的“防乱码、防漏翻”流程

### 第一步：建立翻译清单

先扫描整张图，把所有疑似非中文文本列成清单。每一项至少记录：
- `source_text`
- `source_box`
- `category`（translate / keep / already_cn / uncertain）
- `cn_text`（若需翻译）

**注意：不能一边看一边随意往图上写。必须先形成清单，再统一检查。**

### 第二步：术语统一

基于整张图先建立术语表，再翻译。常用术语优先采用服装行业说法：
- 縫製仕様書 → 缝制规格书
- 芯地 → 粘衬 / 衬布
- 裏 / 裏地 → 里布 / 内里
- 見返し → 挂面 / 贴边
- ロック → 包缝 / 拷边
- ステッチ → 明线 / 压线 / 车线
- 前身頃 / 後身頃 → 前身 / 后身
- 袖口 → 袖口
- 衿 / 襟 → 领 / 衣领
- ラペル → 驳头
- ベント → 开衩
- テープ → 带 / 防伸带
- 接着 → 粘合 / 热压粘合
- 地の目 → 布纹方向 / 纱向

全图必须统一，不允许同一术语一处译成“包缝”，另一处又译成“锁边”，除非上下文明确不同。

### 第三步：中文合规校验（新增）

在真正渲染前，**逐条检查所有 `cn_text`**：

#### 3.1 字符规则

若 `cn_text` 中出现以下情况，必须返工修正：
- 含明显乱码字符：`�`、`□`、异常空框。
- 含大量日文假名（平假名/片假名）。
- 含整句英文或整句日文，说明还没翻译。
- 非必要的大段拉丁字母。

#### 3.2 翻译覆盖率规则

- `translate` 类条目数 = 最终中文批注条目数（允许合并相邻小词，但不能明显漏项）。
- 若一大段内容过密无法逐条都标，可按逻辑合并成一条中文，但必须保证语义覆盖。

#### 3.3 可读性规则

- 所有中文必须由支持简体中文的字体渲染。
- 若当前环境字体不支持，必须切换字体或嵌入字体后再输出。
- 输出前抽查易错位置：页眉、表头、工艺小字、衣片名称、右下备注区。

### 第四步：布局与避让

放置规则不变，但更强调：
- 优先放在原文相邻空白区。
- 近处放不下就改去最近大空白区，并加短引线。
- 表格优先放在本单元格空白处。
- 不跨单元格压住别的内容。

### 第五步：最终质检（强制）

输出前必须逐项核对：

#### 质检清单 A：乱码检查
- 有没有异常方框、问号、替代符号？
- 有没有字形缺失？
- 有没有看起来像日文但被当作中文标出去的内容？

#### 质检清单 B：漏翻检查
- 页眉栏位名是否基本都已译？
- 左侧结构图上的主要工艺词是否已译？
- 右上衣片图及其部位说明是否已译？
- 右侧表头、尺寸名、备注标题是否已译？
- 下方接着条件、裁断方法等是否已译？

#### 质检清单 C：位置检查
- 中文是否压住原文？
- 中文之间是否重叠？
- 是否挡住图线、表格线、尺寸箭头？

任何一项不通过，禁止交付。

## 对模型/Agent的明确执行指令

### 绝对禁止

- 绝对禁止把原文照抄成批注当作“已翻译”。
- 绝对禁止输出乱码。
- 绝对禁止只翻一部分，把另一部分直接留作新增的非中文批注。
- 绝对禁止因为偷懒而跳过密集区域。

### 允许的保守处理

当局部小字过于模糊、无法100%确认时：
- 可结合上下文给出短中文概括。
- 实在无法确定，可标注 `待确认`。
- 但不要瞎编，也不要把日文原句重新贴上去冒充翻译。

## 推荐输出物

默认输出：
1. `*_cn_annotated.png`：最终成品图。
2. `*_annotations.json`：翻译标注清单，便于人工复核。
3. `*_qa_report.md`：质检报告（建议生成），至少写明：
   - 本页识别到多少个 `translate` 项；
   - 最终渲染了多少条中文批注；
   - 是否存在待确认项；
   - 是否通过乱码检查、漏翻检查、重叠检查。

# v3 强化执行规范

## 1. 强制两阶段执行，禁止直接出图

必须严格分为：

### 阶段 A：识别与翻译
先生成完整 `annotations.json`，不得直接开始渲染。

每个检测到的文字项必须包含：
- `source_text`
- `source_box`
- `category`
- `text`
- `confidence`
- `reason`

其中：
- `category=translate` 时，`text` 必须是简体中文译文。
- `category=keep` 时，必须写明保留原因，例如：款号 / 日期 / 数值 / 型号 / 品牌 / 缩写。
- `category=uncertain` 时，不得猜测；`text` 可以写 `待确认`。

### 阶段 B：质检后渲染
只有通过以下检查，才允许将文字绘制到图片上。

---

## 2. 翻译覆盖率硬门槛

必须统计：

- `detected_non_cn_count`
- `translate_count`
- `keep_count`
- `uncertain_count`
- `rendered_translation_count`

要求：

`rendered_translation_count == translate_count`

如果不相等，判定为漏翻，禁止输出最终图。

如果多个相邻短词被合并为一条中文，可通过 `merged_sources` 标记，但必须证明所有源文本均已被覆盖。

---

## 3. 禁止“原文伪装成翻译”

对于 `category=translate` 的条目，必须检查：

- `text != source_text`
- `text` 不得包含完整日文原句
- `text` 不得包含大量片假名/平假名
- `text` 不得主要由英文组成
- 必须至少包含中文汉字，除非该条被分类为 `keep`

若违反任意一项，禁止渲染。

---

## 4. 字体完整性检查

渲染前必须：

1. 明确加载支持简体中文的字体；
2. 对所有待渲染中文字符进行字体可显示性测试；
3. 如果发现缺字、空框、替代字符：
   - 自动切换字体；
   - 重新测试；
   - 仍失败则停止输出。

禁止使用不支持中文的默认字体作为最终回退方案。

---

## 5. 新增“局部复检”机制

以下区域必须单独复检，不能只做一次全图扫描：

1. 页眉 / 标题栏
2. 左侧主结构图
3. 中间局部工艺图
4. 右上衣片图
5. 右侧尺寸表
6. 右下接着 / 备注区域
7. 第二页或长图下半部分

每个区域都要检查：
- 是否存在未分类的非中文文本；
- 是否存在 `translate` 但未生成中文；
- 是否存在新增批注直接照抄原文。

---

## 6. 防遗漏策略

如果页面文字密集，必须采用“区域扫描 + 全图回查”：

### 第一次
按区域识别文字。

### 第二次
从最终图反查：
- 找出仍然可见但附近没有中文批注的日文/英文；
- 判断它属于 `keep` 还是漏翻；
- 若属于漏翻，补译并重新布局。

不得因为区域拥挤而直接忽略。

---

## 7. 布局优先级强化

批注位置按以下优先级：

1. 原文最近的空白区域
2. 同一表格单元格内空白区域
3. 同一结构图内部的空白区域
4. 临近空白区域 + 短引线
5. 远处空白区域 + 引线

禁止：
- 把批注压在原文字上；
- 把批注直接盖住尺寸；
- 把多个批注堆叠在同一狭小区域；
- 为了省空间而缩小到难以阅读。

---

## 8. qa_report.md 必须包含

```text
总识别非中文项：
translate：
keep：
uncertain：
实际渲染翻译项：

乱码检查：PASS / FAIL
未翻译原文检查：PASS / FAIL
翻译覆盖率检查：PASS / FAIL
原文遮挡检查：PASS / FAIL
批注重叠检查：PASS / FAIL
字体完整性检查：PASS / FAIL
```

只要任一项为 FAIL，就禁止把结果作为最终成品交付。

---

## 9. 推荐内部执行指令

执行时必须遵循：

> 不要直接生成图片。先完整识别和分类，再翻译，再做覆盖率与乱码检查，最后才渲染。任何需要翻译的日文或英文，如果仍以原文形式出现在新增批注中，都视为失败。任何中文乱码、缺字、方框字，都视为失败。只有 QA 全部通过后才输出最终 PNG。
