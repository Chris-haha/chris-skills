# Agent 项目任务运行流程

本页供后续会话直接使用，适用于本项目的查询、开发、排障、操作、比较和资料摄入。维护契约见 [schema](AGENTS.md)，页面入口见 [index](index.md)。与项目无关的请求无需加载 Wiki；用户明确的只读要求优先。

## 任务开始：判定交付物并定位知识

先确认用户目标、范围、权限与可验证的完成条件。读取适用项目指令和本库规则；相同会话可复用已读且未变化的内容，不必每条消息重读全部规则。通过 index 先选 1–3 个相关页面，按问题及关联链接扩展。

| 请求类型 | 优先读取 | 工作结果与回流条件 |
| --- | --- | --- |
| 查询/解释 | 主题页；问来历时补 decision，问差异时补 comparison | 回答并附证据；有经核实的新知识且允许维护时才回流 |
| 功能开发/修改 | domain、相关 entity/concept/capability，需要定位实现时查 module | 实际修改并验证；同步受影响事实，不因用过某页就修改它 |
| 缺陷排查/修复 | open-questions、相关 lesson、domain/concept，再查当前实现 | 复现、定位；授权修复时实施并验证，记录可复用根因与处置结果 |
| 构建/运行/操作 | recipe 与必要 capability，结合当前配置 | 实际执行授权操作并检查结果；只更新已验证的步骤变化或问题 |
| 比较/设计 | 相关事实、comparison、decision、约束 | 说明同口径差异与取舍；候选方案不自动成为已采纳决策 |
| 资料摄入 | sources、相关 summary/主题页、授权原件 | 核验范围 → 来源摘要 → 综合页 → 覆盖与互链 |
| Wiki 整理/体检 | schema、index、sources 与目标页面 | 运行体检、内容复核，按授权修正实际问题 |

目录按页面职责选择，不是固定串行清单：module 定位工程归属；domain 解释业务流程；entity 定义对象；concept 解释机制；capability 说明可调用能力；summary 说明来源与去向。不能仅凭 Wiki 的 updated 判断当前实现；涉及当前行为且存在漂移风险时回查代码、测试和原始资料。

## 组织执行：将知识变成动作与验收条件

1. 按需读取 methodology 选择分析/分解方法，recipe 提供具体操作，lesson 提醒已知失败模式，checklist 提供适用的判定条件；有比较或历史选择问题时再查 comparison/decision。
2. 对复杂、跨会话或需要交接的工作，用 template 组织方案、任务与执行记录实例。简单工作在对话中说清目标、动作、产出与验收即可，不强制创建这些文件。
3. 实例保存到当前工作记录位置，使用项目既有约定；没有约定时可采用项目外置记录目录。不得写入 templates 或知识正文。引用重要知识单元时记录 Wiki 内路径与 updated，避免交接后依据不明。
4. 实例是执行指令与验收对照表：执行者读取输入资料、实际执行动作、收集产出，再逐条核对验收条件。保存实例不会自动启动执行，也不能代替真实调查、修改或验证。同一个 Agent 可以先规划再执行。
5. 执行中发现输入缺失、证据冲突或约束不符时修正计划或说明卡点；未知项保持未知，不能为了满足实例要求编造结果。查询请求交付答案，不扩展为用户未要求的代码修改。

## 执行与验收

实际调用可用工具完成授权工作。开发/修复遵守项目构建与测试规则；操作指南的步骤结合当前环境核实后执行；只读调查不产生写入。若没有执行权限或运行能力，交付可应用差异或明确未执行项。

验收对照用户目标与任务实例，给出实际产出、证据及未满足条件。体检只验证知识库结构，不能替代应用测试、事实核验或操作结果检查。原始资料“摄入时只读”不妨碍已授权的代码修改任务修改代码。

## 收尾：先判定影响，再写入知识

在当前任务允许维护且项目规则要求同步时，相关知识一致性属于收尾，不额外要求用户逐页批准；明确只读时只给出候选差异。无新知识或事实未变则无需改页、刷新日期、造摘要或追加无意义日志。规范型页面的变更按项目已有审查约定处理。

从实际差异、验证结果、新来源与已解决问题列出变化，再查来源账本、页面 sources、正文/related 链接找直接受影响页。只检查与本次变化有关的依赖，不无边界遍历全库。

| 页面位置 | 更新触发条件 | 更新方式 |
| --- | --- | --- |
| modules | 模块职责、入口或依赖改变 | 修正档案与关联业务页 |
| domains | 业务流程、规则、边界或实际行为改变 | 修正对应章节与证据，不重写无关部分 |
| entities | 对象定义、字段、状态含义或关系改变 | 更新对象档案；共享机制链接到 concept |
| concepts | 机制解释、约束、适用条件或已知问题状态改变 | 修正机制与关联页；规则未变则保留规则 |
| capabilities | 调用方式、输入输出、权限、错误或边界改变 | 同步契约及行为；生成页走原有生成流程 |
| summaries | 来源新增、版本/内容/覆盖改变 | 复用稳定来源摘要，说明贡献页与缺口；不要求每条用户请求单建来源 |
| comparisons | 比较对象、维度依据或差异改变 | 按相同口径修正表格与结论 |
| decisions | 已确认的重要选择或旧决策被替代 | 新建记录或补状态/替代关系，保留历史 |
| recipes | 操作前提、步骤、预期结果或失败路径改变 | 写入经核实的操作说明，标记未运行部分 |
| lessons | 有证据的新事件、可复用根因或旧事件处置变化 | 提炼教训与适用条件，补处置记录，保留事件事实 |
| checklists/templates/methodologies | 经确认的长期规范或可复用结构需要演进 | 按项目授权及审查规则调整，不由一次事故自动升级规范 |
| tools | 维护脚本存在缺陷或结构演进需要工具支持 | 修改并验证；普通任务只按需运行，不改工具 |

写入步骤：

1. 新来源先建立/更新 summary，再将经核实的事实合并到主要主题落点；原件路径、版本、符号/行号或验证记录作为证据。已有来源增量核验复用其摘要。无法证实的内容进入 open-questions。
2. 更新实质变化页面的正文、sources 与 updated，检查直接关联页和必要反链。新知识优先并入旧页；不要按任务编号不断复制同类知识。
3. 根据变化同步 sources 覆盖、index 新页与摘要、glossary 术语；新问题登记 open-questions，已解决问题保留处置日期、证据与去向。
4. append-only 追加 log，记录来源、受影响页、关键判断与实际验证结果；一次性命令输出与执行轨迹外置，不混入知识正文。
5. 按原有生成流程维护实现/接口文档及 Wiki 派生页，保留人工维护区。此流程不代替项目对文档同步范围的约定。
6. 运行库内体检，复核自包含、证据、覆盖与互链，修复错误并说明警告；缺少工具时报告人工检查范围与未验证项。

## 示例：状态联动缺陷修复后的回流

假设已授权且验证成功：更新领域页中的实际行为、lesson 的修复状态、open-questions 的处置结果，以及内容确有变化的来源摘要；记录证据和日志。若对象定义、联动规则、模块职责都没变，就不修改这些部分。修复普通实现缺陷不自动新增 decision，也不因使用过模板就修改模板。

## 交付

说明用户要求的实际产出、执行过的验证及结果、更新的知识页、尚未完成或未核实项。纯查询无需附空的维护报告；确有过期知识且本次不能更新时说明范围与原因。后续会话仍从项目指令和 index 进入，无需重新输入整套工作流程。
