# 产品原图事实源与表面图案锁设计

## 问题

现有产品一致性清单只锁定部件、连接关系、功能结构和使用状态。杯身花纹、印刷文字及其位置没有独立字段，原始产品图与模板图也没有明确的事实优先级。因此，生成模型可能把花纹当成可近似重绘的装饰，并从模板或历史成图继承错误产品细节。

## 目标

每次生成前必须明确原始产品图是产品外观与结构的唯一事实依据，并逐项锁定表面图案/印刷。缺少任一项时禁止生成；模板只提供版式和视觉语言，历史生成图不能作为产品事实来源。

## 方案

扩展 `ProductIdentity`，增加 `truth_sources` 与 `surface_graphics` 两个必填元组。`product-identity.md` 新增“唯一事实依据”和“表面图案与印刷”区块；命令行新增可重复的 `--truth-source` 与 `--surface-graphic` 参数。

生成提示词将事实源放在产品一致性硬约束的最高优先级，明确：只允许从列出的原始产品图读取产品事实；模板只控制布局；历史生成图即使被提供也不得补充或覆盖产品事实。表面图案要求逐项保持元素、文字、数量、顺序、位置、朝向、比例和线条，不允许同义替换、增删、重排或风格化改写。

交付清单新增事实源核对与表面图案逐项核对。任何不确定或近似都判定为失败并重做。

## 数据流

1. 操作者审阅全部原始产品图。
2. 通过 `set-product-identity` 写入原始事实源文件名与表面图案清单。
3. `write-web-handoff` 加载并验证清单；缺字段直接阻断。
4. 提示词分别标注产品事实源与模板参考图的职责边界。
5. 生成后按交付清单逐项比较原图；通过后才允许批准。

## 错误处理

- `truth_sources` 为空：报“唯一事实依据不能为空”，禁止生成。
- `surface_graphics` 为空：报“表面图案与印刷不能为空”，禁止生成。无图案产品必须显式填写“无表面图案或印刷”。
- 清单未批准或仍有未知项：沿用现有阻断逻辑。

## 测试

- Markdown 往返序列化保留两个新增字段。
- 缺少任一新增字段时验证失败。
- 直接生图提示词包含事实优先级、图案逐项锁和禁止历史成图作为事实源的规则。
- Web 交付清单包含对应核对项。
- CLI 能写入新增字段，缺参数时失败。
