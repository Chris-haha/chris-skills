# AI Hotspot Scout

这个 skill 用来帮你持续追踪 **最新 AI 热点信息**，并把原始信息整理成可直接使用的热点简报。

它的目标不是机械搬运新闻，而是帮助你完成这几件事：

1. 快速发现值得关注的 AI 新动态。
2. 从多个来源交叉验证，避免只看单一信源。
3. 去掉重复、低质量和营销味过重的信息。
4. 提炼出真正值得你继续跟进、选题、转发或分析的内容。
5. 输出结构化结论，方便后续写文章、做口播、做日报或做社媒内容。

这个 skill 追求的是：

- **新**：尽量覆盖最近 24 小时、3 天、7 天内的重要 AI 动态
- **准**：优先使用原始来源、权威媒体、官方公告和高质量社区讨论
- **快**：先给结论，再给来源和上下文
- **能用**：结果可以直接拿去做选题、写内容、汇报或继续研究

## When to Use

在以下场景使用这个 skill：

- 你想知道最近 AI 圈发生了什么
- 你想做 AI 资讯日报、周报、热点追踪
- 你想为公众号、小红书、视频口播、博客寻找 AI 选题
- 你想快速筛选“哪些 AI 信息值得重点关注”
- 你想把零散网页信息整理成一份结构化简报
- 你想区分“真热点”“伪热点”“营销热点”

## Core Outcomes

你要交付的结果通常是以下一种或多种：

- 一份 AI 热点简报
- 一份按优先级排序的热点清单
- 一组适合内容创作的 AI 选题方向
- 一份“信息来源 + 事件摘要 + 为什么重要”的结构化列表
- 一份“今日 AI 热点 / 本周 AI 热点”总结

## Working Principles

### 1. 先找信源，再下结论

不要先凭印象总结热点。

应该先收集来源，再判断哪些真的重要。

优先级默认如下：

1. 官方来源：OpenAI、Google、Anthropic、Meta、Microsoft、NVIDIA、xAI、Mistral、Hugging Face 等官方博客、公告、文档、X 账号
2. 权威媒体：TechCrunch、The Verge、Wired、MIT Technology Review、Reuters、Bloomberg、VentureBeat 等
3. 高质量技术社区：Hacker News、GitHub Trending、Reddit 相关版块、Product Hunt、Hugging Face 社区
4. 高信噪比聚合信息源：论文追踪、模型榜单、AI 新闻站、开发者社区
5. 社交讨论：X / Twitter、YouTube、微信群转述类内容

如果一个热点只有社交平台讨论，没有可信来源支撑，默认降低可信度。

### 2. 热点不等于热闹

很多内容看起来传播很大，但未必重要。

要优先识别这些真正值得关注的热点：

- 新模型发布
- 关键能力升级
- API、价格、上下文窗口、推理能力等重大变化
- 重要融资、收购、组织变动
- 开源项目爆发式增长
- 新产品快速破圈
- 行业政策、监管、版权、数据合规变化
- 会明显影响开发者、创作者或企业应用落地的信息

默认降低优先级的信息：

- 纯宣传口径，没有实质更新
- 内容农场式搬运
- 只讲“震惊”“颠覆”，但没有细节
- 明显标题党
- 重复转述的二手信息

### 3. 优先识别“为什么这条信息重要”

每条热点都不能只写“发生了什么”，还要回答：

- 这对谁重要？
- 它会改变什么？
- 它和之前相比有什么新意？
- 它值得继续跟进吗？
- 它更适合拿来做新闻、观点、教程，还是案例解读？

如果说不清这几点，这条热点默认不应排到前面。

### 4. 去重、并源、聚合同一事件

同一个热点经常会在多个站点重复出现。

你要把这些信息并成一个事件，而不是机械罗列多个链接。

正确做法：

- 合并相同事件的多个来源
- 保留最权威的原始来源
- 用其他来源补充背景和影响
- 明确区分“原始消息”和“二次解读”

### 5. 对内容创作要有转化意识

这个 skill 不只是新闻整理器。

它还要把信息转成适合创作的线索，比如：

- 哪些热点适合写深度解读
- 哪些适合做短内容快讯
- 哪些适合做教程或实操演示
- 哪些适合做观点型内容
- 哪些适合做“趋势判断”或“行业影响”内容

### 6. 默认做时间窗筛选

如果用户没有特别说明，默认优先关注：

- 最近 24 小时：高时效热点
- 最近 3 天：中短期热议事件
- 最近 7 天：本周最值得关注的趋势

如果用户只说“最新”，优先按最近 3 天处理，并补充最近 24 小时的重点变化。

### 7. 默认输出中文，但保留英文专有名词

输出给用户时，默认用中文说明。

但模型名、产品名、公司名、论文名、仓库名保留英文原名，避免失真。

## Input Checklist

开始前先确认：

- 用户是想看今日热点、近 3 天热点，还是本周热点？
- 用户更关心哪类信息：模型、产品、开发、融资、开源、政策、研究？
- 用户最终要拿这些信息做什么：选题、写稿、汇报、学习、投资观察？
- 用户希望更偏“快讯”，还是“有分析的简报”？
- 用户要不要附上原始来源链接？
- 用户要不要额外产出选题建议或内容角度？

如果这些信息不完整，优先按默认策略执行，不要过度追问。

## Default Source Strategy

当需要抓取最新 AI 热点时，默认按下面的顺序搜集：

1. 先看官方与一手信源
2. 再看主流科技媒体的最新 AI 相关报道
3. 再看开发者社区和开源社区的异常热度项目
4. 最后看高质量社交讨论，补充传播热度和情绪判断

默认优先关注以下来源类别：

- 官方博客 / 官方公告 / 官方 X 账号
- TechCrunch / The Verge / Reuters / Bloomberg / Wired / VentureBeat
- Hugging Face / GitHub Trending / Hacker News / Product Hunt / Reddit AI 相关社区
- 必要时补充 YouTube、播客、个人博客，但要降低信任等级

## Workflow

### Step 1: 明确时间窗和关注范围

先判断这次任务属于哪一种：

- 今日 AI 热点
- 最近 3 天 AI 热点
- 本周 AI 热点
- 某个具体方向的 AI 热点，例如 AI Agent、RAG、开源模型、AI 视频生成

如果用户没有限定，就默认执行“最近 3 天 + 最近 24 小时重点提醒”。

### Step 2: 多源检索

从不同类型来源搜集候选热点。

建议至少覆盖：

- 2 个以上官方或一手来源
- 2 个以上媒体来源
- 1 到 3 个社区或开源来源

对于每条候选信息，至少记录：

- 标题
- 来源
- 发布时间或相对时间
- 核心事件
- 是否为原始来源

### Step 3: 去重与聚合

把讲同一件事的内容并在一起。

对每个聚合后的热点，整理出：

- 事件名
- 一句话摘要
- 关键事实
- 主要来源
- 补充来源
- 当前热度判断
- 可信度判断

### Step 4: 评估优先级

按下面维度给热点排序：

- 影响面是否大
- 时效性是否强
- 是否有明确事实支撑
- 是否会影响开发者、创作者或企业应用
- 是否有后续讨论空间
- 是否适合用户当前目标

可将热点粗分为：

- S 级：强烈建议优先关注
- A 级：值得关注
- B 级：可快速浏览
- C 级：噪音或观察项

### Step 5: 输出结构化简报

默认输出结构建议如下：

1. 今日 / 本周最重要的 3 到 5 条 AI 热点
2. 热点清单（按优先级排序）
3. 每条热点的“发生了什么 + 为什么重要 + 建议关注点”
4. 如用户有内容创作需求，再补充可做的选题方向

## Output Modes

### Mode A: 快讯版

适合只想快速扫一眼。

输出：

- 3 到 10 条 AI 热点
- 每条 1 到 3 句话
- 附来源

标准：

- 快
- 短
- 信息密度高
- 不展开长分析

### Mode B: 简报版

适合做日报、周报、内部同步。

输出：

- 按优先级排序的热点列表
- 每条包含摘要、重要性、来源、建议关注点

标准：

- 结构清晰
- 有判断
- 有取舍
- 不堆砌链接

### Mode C: 选题版

适合内容创作者。

输出：

- 热点简报
- 每条热点可延展的内容角度
- 可做标题方向、口播方向、文章方向

标准：

- 不只是报道热点
- 要把热点转成可写、可讲、可传播的选题

## Deliverable Template

默认优先按这个顺序组织结果：

1. **时间范围**
2. **最值得关注的 3-5 条热点**
3. **完整热点列表**
4. **每条热点的来源与判断**
5. **如果用户是内容创作者，再追加选题建议**

每条热点默认包含：

- 热点名称
- 事件摘要
- 为什么重要
- 主要来源
- 补充来源
- 建议关注点
- 优先级

## Quality Bar

产出前检查：

### 信息质量检查

- [ ] 是否覆盖了多个来源，而不是单一来源
- [ ] 是否优先使用了一手来源
- [ ] 是否避免了明显营销稿和标题党
- [ ] 是否去掉了重复事件
- [ ] 是否区分了“发生了什么”和“为什么重要”
- [ ] 是否明确了时间窗

### 结果可用性检查

- [ ] 用户能否快速看出最重要的几条信息
- [ ] 用户能否继续拿这些信息做内容创作或研究
- [ ] 是否给出了必要的来源指引
- [ ] 是否有清晰优先级，而不是平铺罗列

### 判断质量检查

- [ ] 是否解释了热点的影响面
- [ ] 是否说明这条信息对谁有价值
- [ ] 是否避免把噪音误判为热点
- [ ] 是否保留了不确定性说明

## Do This / Not That

### 做 AI 热点抓取时

Do This:
- 先看一手来源，再看二手解读
- 合并同一事件的多条报道
- 明确写出“为什么重要”
- 保留来源名称和发布时间信息
- 优先给出结论和优先级

Not That:
- 到处复制一堆链接
- 把同一事件拆成多条重复热点
- 只写“很火”，不解释为什么
- 只看社交平台，不做验证
- 只按标题热度排序，不看真实影响

### 给创作者做信息整理时

Do This:
- 把热点转成选题线索
- 识别适合做观点、快讯、教程、案例的不同方向
- 优先挑有传播性和讨论空间的事件

Not That:
- 只给新闻摘要，不给内容转化思路
- 把所有热点都写成同一种风格
- 完全忽略用户的创作目的

## Default Response Strategy

当用户只说“帮我抓一下最新 AI 热点”时，默认这样处理：

1. 先按最近 3 天做搜集
2. 补充最近 24 小时的新增重点
3. 覆盖官方、媒体、社区三类来源
4. 先给 3 到 5 条最重要的热点
5. 再给完整热点列表
6. 如果用户有创作需求，再补充 3 到 5 个可延展选题

如果用户提到以下方向，默认额外加强对应来源：

- 提到 `AI Agent`：加强框架、开源项目、开发者社区、产品发布
- 提到 `RAG`：加强检索、向量数据库、知识库、评测、开源方案
- 提到 `开源模型`：加强 Hugging Face、GitHub、模型榜单、论文与仓库
- 提到 `AI 产品`：加强 Product Hunt、主流媒体、官方产品页、用户反馈
- 提到 `政策监管`：加强 Reuters、Bloomberg、政府或官方发布渠道

## Example Requests

- “帮我抓一下最近 24 小时最值得关注的 AI 热点。”
- “整理最近 3 天的 AI Agent 热点，按重要性排序。”
- “帮我做一份本周 AI 热点简报，适合发团队群。”
- “抓取最新 AI 资讯，并给我 5 个适合公众号的选题角度。”
- “帮我筛选最近值得做视频解读的 AI 热点。”
- “整理最近开源大模型方向的热点，附来源和你的判断。”

## Final Rule

永远不要把“信息很多”误当成“信息有价值”。

宁可少一点，也要更准。
宁可慢半步，也要更可信。
宁可先给 3 条真正重要的，也不要给 20 条无效噪音。
