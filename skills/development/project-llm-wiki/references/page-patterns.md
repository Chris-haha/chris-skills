# 页面写作参考

每页只承担一个主题；共享事实保留一个主要落点并从其他页互链。标题与正文语言遵循项目约定。下列是可删减的写作结构，不要求每页凑齐固定章节或固定字数。

| 类型 | 最小有效内容 |
| --- | --- |
| overview | 项目用途、当前形态、主要组成、阅读路线、全局约定与未知边界 |
| module | 职责、输入输出、依赖、入口/关键文件、关联领域与边界 |
| domain | 领域目标、核心流程、规则/数据、正常与异常路径、关联知识单元 |
| capability | 谁能使用、前提、调用方式/输入输出、权限/错误/边界、关联领域 |
| entity | 定义、标识、状态/生命周期、关键字段语义与关系 |
| concept | 解决什么问题、机制、适用范围、与本项目的关系 |
| summary | 来源身份/版本/范围、要点、证据性质、知识去向、缺口 |
| comparison | 比较对象、口径、差异及依据，避免没有证据的排名 |
| decision | 状态/日期、背景、决策、后果、证据与后续替代关系 |
| recipe | 任务视角、前提、可复现步骤、预期结果、失败分支；未运行命令注明 |
| lesson | 已发生事件、证据、原因、经验证的教训、适用条件 |
| checklist | 任务视角、可判定条件、每条依据与失败处置 |
| template | 任务视角、可复用结构、填写与验收规则，不放一次性实例 |
| methodology | 任务视角、问题分类、决策/分解方法、已验证先例与边界 |

通用知识页示例（变量与示意路径不能原样保留为确认事实）：

```markdown
---
type: concept
updated: YYYY-MM-DD
sources:
  - src/example.ext
related:
  - ../domains/example.md
tags: [检索关键词]
confidence: medium
---

# 主题名称

## 核心结论

已核实结论及适用范围；证据写 `src/example.ext:符号或行号`。

## 机制与边界

解释输入、过程、输出及失败条件。推断单独标注，证据不足记入未确认项。

## 关联知识单元

- [关联领域](../domains/example.md) — 说明关系。
```

规范型页面的 `## 任务视角` 正文说明适用任务、输入、产出与前置条件，不把这些解释性段落塞进 frontmatter。新领域页只链接确实存在且相关的知识单元；实体/概念页同步反向链接，不创建无内容页面来凑链接数。

模板还应说明实例的消费者与用法：方案实例供执行者安排任务与依赖；任务实例供执行者读取输入、开展动作并逐条验收；执行记录实例供执行者记录事实、检查者复核证据与偏差。实例外置，模板只维护可复用结构；保存实例不自动启动执行，也不能替代真实产出。复杂任务按需使用，简单工作无需为了满足模板而创建文件。

来源摘要的 `## 知识去向` 应列出实际贡献页及贡献内容。`sources.md` 的一行对应稳定来源单元；多个小文件成组时在摘要列出清单和逐项覆盖，partial 明确未摄入部分。

大型参考页按独立主题拆分并保留总目，而非复制导航和公共约定。若明确要求字段级完整摄入，按适用范围逐项核对字段、错误、边界与覆盖数量；一般首轮搭建不自动扩大成全项目接口审计。
