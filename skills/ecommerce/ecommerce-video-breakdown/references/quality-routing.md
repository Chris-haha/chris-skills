# 口播质量与分析方式

原始ASR是识别结果，不自动等于口播。始终保留原稿与清理稿，不用语义补写修复乱码，不把标题、正文或AI摘要塞进逐字稿。

| 资料情况 | 操作与边界 |
|---|---|
| 平台字幕／人工导入全文 | `speech`；逐段核对，商品声称仍非实证。来源如实填写，不把ASR改名为人工导入绕过核听 |
| 自动转录未经核听 | 默认 `pending_review`，禁止口播引用；有画面自动选 `visual`，无画面待核听或补画面 |
| 短词、重复歌词、乱码、语义不通 | 记录 `unusable` 和具体理由；只提示风险，不能证明视频没有人声 |
| 有画面，口播无用／缺失／未核听 | `visual`，依据标题、正文、亲自查看的画面拆解14模块；缺少口播结构明确写缺失 |
| 已核听全文并检查画面 | 可选 `mixed`；口播、画面、正文分别引用 |

先读 `index` 和 `prepare` 提供的证据路径，再记录复核决定。例如：

```bash
python3 scripts/video_breakdown.py review --workspace <工作区> --video-key <键> --narration unusable --mode visual --basis text_review --reason '识别文字是无关短词，不能支持商品口播分析；未核听音轨'
```

ASR确认 `usable + speech/mixed` 要求 `--basis audio_review`，仅在实际核听对应音轨并确认全文后使用。工具记录依据，不能代替听音。未核听时允许完成视觉报告，不必为报告反复转录。

复核不会下载、转录或覆盖人工分析；质量、方式、正文及画面纳入新证据指纹，旧分析需复核。刷新资料会重置审查，旧记录留在 `quality_reviews` 或原稿修订中，不能沿用旧的可用结论。

## 视觉报告的证据纪律

- `title` 是标题，`caption` 是笔记正文，`frame` 是看过的画面。正文的材质、功效、情绪或他人反馈写“发布者声称”，不升级为实测或真实评论。
- 抽帧仅证明抽样时刻，不能证明连续动作、剪辑切点、语速、音乐、人声有无或留存。画面文字可在 `frame.inspection_note` 中短引，注明真正辨认的内容，不另造逐字稿。
- 当前发布账号和正文署名的原创作者分别记录，不自动当同一人或店铺。概念／合成影像未核实，不作为实拍商品证明。
- “戴半年变好了”等标题可分析情绪机制，不能验证运气、健康、销量；也不能从反光证明材质、气味或舒适度。
- 报告展示分析方式、口播质量、未检查项、正文来源时间。旧 `#transcript` 地址仍保留，指向“未采用的语音识别结果”。
- 分别统计媒体取得数、检查帧数、可用口播数、完成视觉分析数。视觉分析通过不能写成转录成功。
