# 一份 Excel，持续补充

导出前和保存后的文字验收见 [成品文字审读](editorial-check.md)。更新已有分析时保留 `export_id`（若存在），即使修改拍法或准备项目的名称，也用原编号更新原行，避免旧文案残留和备注错位。没有 `export_id` 的历史数据仍使用原有编号规则。

最终交付为同一份 `reports/电商视频分析总表.xlsx`。HTML用于回看原片、画面和出处，不再让用户从多个报告文件中挑成品。

导出将同一段落的续行排在一起。拍法库中，同一视频的完全重复说明折叠显示，原数据仍在；含备注或自建列内容的行不折叠。`--previews` 从最终保存的Excel重新读取生成，不能用导出前预览代替。

## 新链接与已有总表

同一语料库沿用同一 `--workspace`，先检查归档索引和 `.excel-export.json`。用户说“追加到之前那份”时沿用记录的Excel路径，不新建带日期的工作簿或工作区。新链接完成归档、逐条分析和博主全量归纳后，运行：

```bash
python3 scripts/video_breakdown.py render --workspace <原工作区>
```

`render` 默认更新Excel并刷新图文报告。只补导出、不做新解析时使用 `export-excel --workspace <原工作区>`。首次指定总表位置可加 `--output <文件.xlsx>`（render使用 `--excel-output`），后续自动记住此路径。新增链接必须先进入原归档并分析，往Excel粘贴一个URL不会触发解析或分析。

## 工作表

| 工作表 | 内容 |
|---|---|
| 博主汇总 | 平台与账号、累计视频数、已分析／待补数量、主要结论、人工备注 |
| 视频索引 | 每条视频的结论、待补信息、状态、原视频与图文报告链接 |
| 博主分析 | 全量归纳的六个方面、拍法组合、覆盖视频与限制 |
| 视频拆解 | 十四模块、原视频分段、实际依据 |
| 拍法库 | 原片做法、为什么值得学、自己的拍法、条件、比较方法及元素卡 |
| 拍摄脚本 | 每个镜头的拟拍时间、画面、口播、字幕和准备事项 |
| 拍前准备 | 商品待确认信息、补拍、素材、发布前核对与两版比较 |

长段落拆为连续记录完整保存，不能截取前几条或截断单元格。原片时间与新脚本拟拍时间分开，商品未知信息保留待填，仍使用普通拍摄语言。

## 更新规则

- 视频按平台视频ID与B站分P识别；博主按平台账号区分，昵称相同不合并。明细按“记录编号”更新，不靠行号，因此筛选、排序后备注仍跟随原记录。
- 新记录追加；已存在记录更新自动分析列；“我的备注”、用户增加的列及工作表保留。自动分析列由归档分析维护，人工补充放在备注或自建列。不要修改记录编号、账号编号、视频编号和表头。
- 某条分析失效或减少时，旧明细连同备注保留，明确标为“历史保留，本次不采用”。不得把旧结果继续当有效分析。视频索引和待补数量同步更新。
- 更新前备份到工作区 `backups/excel/`；生成失败、目标重复编号、表头损坏或外部同时改文件时停止，保留原Excel。输出使用文件锁和原子替换。损坏或其他来源的工作簿不覆盖。
- 同一批重复运行不得新增相同记录。已有语料不重新下载、转录；严禁登录态的规则不变。

## 验收与交付

用隔离副本验证：新批次追加、重复导出、已有分析更新、排序后备注、自建列和工作表、失败保护、旧结果失效标记。真实成品应核对博主数、视频数、十四模块和逐镜头覆盖，不能只检查表头。

加 `--previews <验收目录>` 可从最终文件生成七张工作表预览。有表格工具时为PNG，无该工具时为HTML；以结果记录为准，不能将HTML声称为截图。逐表查看文字完整性。实际浏览器地址上的Excel下载按钮应下载同一文件，刷新后可用。只把最终 `.xlsx` 作为分析主交付；新增链接继续补入这份表。

当前Codex可用表格环境时优先使用 `@oai/artifact-tool`，可通过 `load_workspace_dependencies` 定位，或配置 `CODEX_SPREADSHEET_NODE`、`CODEX_NODE_MODULES`。缺少它或Node时使用随包的标准库XLSX写入器，不要求复制本机私有运行时。两种路径都执行同一数据、证据和文字检查。复制整个工作区到另一台电脑时，工作区内的总表按相对位置恢复，不继续引用旧电脑的绝对路径。
