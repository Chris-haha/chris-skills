# 搭建新 Wiki

## 发现与选址

读取目标项目及父级约束、现有 README/文档入口、构建或资料目录。先检查是否已有知识库；存在时按它的 schema 增量维护。用户要求迁移时先列出路径和字段对应，保留原件与可恢复差异，勿覆盖现有内容。

默认 `docs/wiki/`，用户可指定项目内其他路径。项目名从已核实的文档中获取；无法判断时用目录名并说明。输出语言跟随用户或项目，英文文件名采用 kebab-case。不要继承示例项目的模块、业务实体、技术栈、凭证路径或 Git 忽略策略。

## 创建骨架

识别实际宿主的项目指令入口，再运行 `scripts/wiki.mjs init --entry-file 项目内规则文件`；先 dry-run 确认计划，再真实创建。已有目标非空时脚本拒绝继续；应阅读现有内容并做有依据的合并，不能删除旧目录来绕过保护。仅制作骨架包或无法确认宿主入口时可省略 entry-file，但必须报告未接入。

手工方式：复制 `assets/wiki/` 到 Wiki 根目录，将 `{{PROJECT_NAME}}`、`{{WIKI_PATH}}`、`{{DATE}}` 替换为实际值；把 `scripts/wiki.mjs` 复制为 `tools/wiki.mjs` 以提供可选体检。项目名只用于正文；不要把文件内容拼进 shell 命令。无需为了凑目录预建所有页面类型。

最小产物为 `AGENTS.md`、`agent-workflow.md`、`index.md`、`overview.md`、`glossary.md`、`sources.md`、`open-questions.md`、`log.md` 和 `raw/` 说明。运行流程随 Wiki 保存，后续会话不依赖技能目录。默认只有 raw 原件被局部忽略，知识页应可共享；检查实际 Git 忽略规则，如已被忽略则报告，只有用户要求更改共享策略时才修改。

## 首轮摄入

1. 盘点可用来源：说明文档、代码/测试/配置、已有实现手册、设计记录、事故记录、用户提供材料。只读与本次范围有关的文件，跳过二进制生成物、依赖目录、凭证和私人资料。
2. 先建立 `sources.md` 账本，标记 pending / partial / ingested / excluded，不把列出路径当成已摄入。
3. 选择足以回答“是什么、主要组成、怎么开始、已知边界”的来源，依照 Ingest 流程填充总览、术语、来源摘要及必要知识页。小项目一个主题即可；大项目首轮有界，明确后续缺口，不能默认承诺全仓库审计。
4. 无真实来源的空项目只完成骨架，保留明确的待确认项并报告缺少哪些资料；不编造总览、运行命令或业务页。
5. 页面互链、index 登记、来源状态与 log 同步后运行体检，并按普通读者视角检查自包含程度。

## 接入 Agent 入口

初始化目标项目时，将 [assets/project-entry.md](../assets/project-entry.md) 的规则接入宿主实际读取的项目入口；替换 Wiki 路径，保留原文件其他内容及换行。该规则同时指向 schema、运行流程与 index，覆盖项目任务的知识读取、实际执行、验收及按影响回流。如果当前请求仅制作/改造技能包，不改当前项目或任何示例项目的规则文件。

选择接入方式：

- **新库、新入口**：`init --entry-file ...` 同时创建 Wiki 与入口。省略 entry-file 的调用只生成骨架，不算完成后续会话接入。
- **已有库、已有标记块**：先读旧 schema，将通用运行流程适配合并为 agent-workflow，登记 index，并在 schema 合适位置链接；再用 `connect --entry-file ...` 更新标记块。勿覆盖旧 schema 或重跑 init。
- **已有等价的非标记段落**：由 Agent 就地合并缺少的执行/回流规则；不要再追加一段重复规则。合并后也要确保路径有效与实际运行流程存在。
- **非 Markdown 入口或特殊宿主格式**：按宿主实际规则机制手工适配模板。脚本仅支持项目内 Markdown/mdc 文件，不创建多个宿主配置，也不猜测格式或自动加载能力。

脚本接入支持 dry-run、保留标记块外字节及既有换行、重复执行幂等。标记损坏/重复、原文件非 UTF-8 或含 BOM 时拒绝改写；保留原文件并由 Agent 在项目约定内形成可审查合并，不为接入批量转码。脚本不会识别无标记文本的语义等价，执行前必须人工式阅读检查。

支持 AGENTS.md 的宿主可接项目根该文件，其他宿主用实际支持的入口。完全不读取项目规则的环境，在新会话开头显式要求读取 schema、agent-workflow 与 index，无需每条问题重复提示。确认文件路径及内容可达；只有有证据确认宿主加载时才声称已自动生效，否则报告已写入的入口和未验证的加载状态。

## 完成条件

- 维护规则、目录和实际项目匹配；无未替换的模板变量或借用示例项目的业务结论。
- 已读取来源对应真实摘要及知识页，总览能够回答首轮范围内的问题。
- index 覆盖全部知识页，关键主题有有意义的双向互链；sources 诚实反映已摄入与缺口。
- log 有追加记录，open-questions 有明确影响及查证动作；不得把待核实内容混成确认事实。
- 实际执行体检并报告结果，或给出已做的人工检查及未执行自动检查的原因。
- 运行流程已在 Wiki 内自包含，实际项目指令入口已合并且没有重复；说明入口路径及加载验证范围。用户只要求模板/骨架或环境无法接入时明确区分未接入状态。
