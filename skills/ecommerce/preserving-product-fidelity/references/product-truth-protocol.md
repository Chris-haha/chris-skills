# 产品事实与验收协议

## 1. 证据层级

按以下优先级处理信息：

1. 用户提供的产品原图及局部原图。
2. 用户对这些原图的明确纠正或确认。
3. 目标模特图中的姿势、遮挡、尺度和场景信息。
4. 生成候选图，仅用于发现错误，永远不能证明产品事实。

同类商品经验、品牌常见结构、搜索到的图片和“物理上更合理”均不属于证据。除非用户明确授权并确认完全相同的 SKU，否则不得用外部图片补全不可见结构。

## 2. 产品事实表

生成前建立下表。重要事实必须能指回某张原图的具体区域。商业执行还必须将它保存为[结构化 manifest](fidelity-manifest.md) 中的 `facts`，并保留来源路径、SHA-256 和归一化证据区域；表格不能替代机器验证。

| ID | 部件/属性 | 数量 | 已观察事实 | 证据位置 | 状态 | 商业重要性 | 禁止变化 |
|---|---|---:|---|---|---|---|---|
| P1 | 整体轮廓 | 1 |  |  | 已观察/用户确认/未知 | 高 |  |
| P2 | 承重部件 |  |  |  |  | 高 |  |
| P3 | 闭合部件 |  |  |  |  | 高 |  |
| P4 | 五金/logo/文字 |  |  |  |  | 高 |  |
| P5 | 口袋/翻盖/开口 |  |  |  |  | 高 |  |
| P6 | 材质/纹理/缝线 |  |  |  |  | 高 |  |
| P7 | 尺寸与比例 | 1 |  |  |  | 高 |  |

状态定义：

- **已观察**：像素中直接可见，不依赖类别推断。
- **用户确认**：用户明确解释了容易误读的关系。
- **未知**：遮挡、分辨率或单一角度不足以判断。
- **冲突**：原图或解释之间互相矛盾，尚未解决；JSON 状态为 `conflict`。

禁止用“高置信猜测”替代“未知”。

### 用户批准只作用于明确事实

`approval.confirmed_fact_ids` 必须逐条登记用户明确确认的事实或拓扑 ID，并在任务记录中保留用户原话及其所解释的原图区域。`user_confirmed` 仍须有产品原图证据，不得据此创造图中完全没有展示的构造。已经明确确认的同一事实无需反复询问。

泛泛的“确认”、预览或构图批准、继续操作许可、允许保留泡棉或其他包装，都不能消除未知结构。包装许可只改变允许保持遮挡的范围；它既不能证明遮挡下的数量、端点或路径，也不能支持“只有一个”“没有第二个”等否定断言。

## 3. 连接拓扑表

对所有带、链、绳、手柄、扣件、环、拉链和装饰件逐个填写：

| 组件 ID | 用途 | 独立组件数 | 起点 | 路径 | 终点 | 连接类型 | 是否承重 | 遮挡/未知 |
|---|---|---:|---|---|---|---|---|---|
| C1 |  |  |  |  |  | 固定/铰接/滑动/贯穿/未知 | 是/否/未知 |  |

追踪规则：

- 从一个真实端点连续追到另一个端点，再计为一个组件。
- 可见的两个弧段可能属于同一个组件；一个弧段也可能遮住多个组件。不要按弧线数量判断。
- 明确区分承重系统、闭合系统和装饰系统。外观相似不代表用途相同。
- 分别记录“接触在一起”和“机械连接”。相邻、遮挡或透视重叠不等于贯穿或固定。
- 对每个顶端和连接点放大检查：链路是否结束、返回、穿过、绕过、隐藏在后方，还是证据不足。
- 任何无法闭合的连接图都应标记为未知，不能靠常识补完。

## 4. 不确定性闸门

以下项目若未知或冲突，且最终会可见或必须重绘，就在生成前停止并请求更清晰的局部图、背面图、侧面图或连接点特写：

- 带子、手柄、链条或绳子的数量、端点、路径与承重关系；
- 开合方式、孔洞、扣件、磁吸、铰链、挂钩或可拆卸关系；
- logo、文字、五金数量与位置；
- 口袋、开口、拼接、缝线、图案连续性；
- 会改变商品功能、规格、身份或购买判断的任何细节。

允许保留的未知项必须在最终画面中保持不可见且不重绘。明确登记需隐藏的区域，并确认可见轮廓也不会暗示某个未经证明的结构。提示词应写“保持遮挡，不要补全”，而不是描述一个猜测版本。所有可见或重绘的高重要性事实与拓扑都要登记在 `scene_plan` 的身份区域 ID 列表；不能通过漏填、降级重要性或换成草稿模式规避商业闸门。

### 来源支持的展示范围

在制作场景前，建立 `scene_plan.presentation_envelope`：由原图证明的方向、表面、连接点及必须隐藏的区域。视图不完整时，调整模特姿势、手的位置、裁切和商品位置，仅展示来源支持的角度与表面，未知区域保持隐藏。模特原姿势不能授权新产品视角；产品事实优先于复刻原模特图的持包方式。

只有正面图时，只做不显露未知侧面、背面、底面、开口或内部连接的正面展示。三分之四视图只证明实际拍到的那一侧和角度，不能拓展为任意转角。禁止用镜像或类别常识补全另一侧；商业模式的 `mirrored_product_view` 必须为 `false`。先记录获准的场景调整，再执行这些调整；保持人物身份与整体视觉方向，不改变商品形状来迁就姿势。若支持范围内没有自然的构图，停止并请求缺失角度、改为保持遮挡的构图，或转入另行验证的真实 3D 资产流程。

### 参考预算与证据保全

参考图上限不是丢弃证据的许可：每张必要产品来源都必须直接选入，或纳入有可追溯 provenance 的确定性证据 atlas；无法保持完整且可读时停止。不能为了满足上限而将必要来源改成 `required: false`。

atlas 只能用原图确定性裁切、排版和缩放，记录原图及 atlas 文件 SHA-256、父来源 ID、源区域到 atlas 区域的映射和实际缩放；不得生成式重画。关键部件必须在最终参考尺寸仍然可读，名义上覆盖但细节缩小到不可辨认不算保全。原始来源继续保留，atlas 只承载证据，不产生新事实。

## 5. 方法选择

| 方法 | 能力与边界 | 交付上限 |
|---|---|---|
| `deterministic_composite` | 默认。复用原产品像素，只做来源支持的摆放、几何映射、遮挡和光影匹配；登记受保护区域及可复现变换，`product_pixels_preserved: true` | 完整 QA 和验证后可为 `verified_composite` |
| `masked_generative_contact` | 工具必须同时暴露显式遮罩与图层锁，`supports_mask`、`supports_layer_lock` 均为 `true`；产品身份区域受保护，仅编辑最小手部遮挡、接触或阴影区域，保留产品像素 | 满足保护能力与完整 QA 后可为 `verified_composite` |
| `evidence_constrained_generation` | 面向模特手持或穿戴商品时的自然重建。先由产品视角证据决定最终角度，再让模特姿势、手位和裁切适配商品；只重建已获证据支持的可见表面与身份事实，所有可见身份 ID 均登记为 redrawn；未知表面继续隐藏 | 结构 landmark 与独立材质 QA 均通过后可为 `verified_reference_match`；不是像素复用证明 |
| `full_generative_redraw` | 整件产品重新生成，任何模型名称、订阅等级、漂亮观感和预览批准都不能证明精确复用 | 最高为 `unverified_draft`，不得标记为 `verified_composite` |

`evidence_constrained_generation` 不是不受限制的全量重绘。它必须将 `product_pixels_preserved` 记为 `false`，列出 `view_anchor_source_ids`，且锚点必须覆盖最终产品方向所需的产品/局部原图；所有会在候选中出现的身份事实均须有证据并进入 `redrawn_identity_critical_regions`。若某个结构、侧面、开口或连接关系没有证据，就通过商品角度、模特姿势、手部遮挡或裁切使其不出现，不能猜测或镜像补全。

材质身份是阻断项，不是美化项。把颜色、纹理/粒面尺度与方向、反射与光泽、软硬挺括度、缝线和五金表面响应分别登记为事实；`method.material_identity_fact_ids` 必须引用其中有原图证据、会被重建的高重要性材质事实，且 `material_fidelity_required: true`。候选必须在原始分辨率完成 `qa.material_comparison`；任一材质事实缺失、塑料化、蜡化、过度磨皮、错误增亮/变哑、纹理尺度漂移或五金反射失真，都应拒绝。

若任务要求像素级精确替换，但工具只有全量重绘或无法验证遮罩与图层锁，停止商业执行，改用确定性合成、补拍或另行验证的真实 3D 资产流程。若目标是模特自然手持且允许证据约束重建，可在上述闸门内使用 `evidence_constrained_generation`。不得通过生成一张“试片”绕过方法闸门；概念草稿只能明确标注为未验证，不能冒充商业结果。只在工具实际披露时记录模型名称。

商业首张候选之前，必须按 [manifest 的预检流程](fidelity-manifest.md#验证命令与两个闸门)运行验证器并要求退出码 `0`。预检 QA 保持未完成、状态为 `unverified_draft`，不能预填通过。任何来源、事实、方法或构图计划变更都要重新预检。

### 保真优先的质量闸门

只有产品身份、模特身份、场景不变量、接触关系和连接拓扑均按本协议通过后，才能开始[质量修复协议](quality-restoration-protocol.md)；任一项未通过或未解决时，不得用清晰度或质感修复推进。

任何质量处理后，都必须从头重做本协议的完整产品、模特与场景检查，并按[质量修复协议的多尺度 QA](quality-restoration-protocol.md#8-多尺度-qa)复核遮挡、伪影和输出元数据；修复前的 `PASS` 不得继承。

任何新增、补画或强化的毛孔、发丝、织物织纹、商品材质颗粒、缝线、边缘定义、logo/文字边缘、五金边缘或其他看似合理的微细节，若无相应原始来源支持，均属于幻觉细节，而不是恢复的清晰度。商品视觉证据仍只能来自 `PRODUCT_TRUTH` / `DETAIL_TRUTH`；用户明确确认只可消除这些图像中的歧义，不得补造未展示事实。人物与场景纹理只能来自 `TARGET_SCENE`。

## 6. 提示词合同

每条产品结构断言（包括数量、用途、连接方式、“只有”“没有第二个”和禁止变更）必须先进入 `prompt_claims`，由 `supporting_ids` 追溯到已解决且有原图区域证据的事实/拓扑 ID；独立禁止变更也可记录为同结构的 `forbidden_mutations`。未知或冲突 ID 不能支持正向或反向断言。运行 `python3 scripts/validate_fidelity_manifest.py --emit-prompt-contract MANIFEST.json`，只使用验证成功后输出的 `prompt_contract`，保留支持 ID；场景风格另写，禁止在合同外自由补写产品结构。验证器校验支持引用并导出合同，不能判定一句话是否真正被像素或所引断言蕴含，执行者必须逐句核对。

按以下结构写提示词，并删除所有没有证据的句子：

```text
TASK
只把 TARGET_SCENE 中的原商品替换为 PRODUCT_TRUTH 中的商品。

REFERENCE ROLES
- TARGET_SCENE: 只提供人物、姿势、构图、背景、光线和接触位置。
- PRODUCT_TRUTH: 商品外观与结构的唯一视觉事实来源。
- DETAIL_TRUTH: 只解释指定局部，不扩展到不可见区域。

OBSERVED PRODUCT FACTS
- [事实 ID]: [原图证据支持的数量、轮廓、材质、纹理、五金、文字及明确关系]

TOPOLOGY
- [组件 ID]: one open/closed path; endpoint A -> route -> endpoint B;
  attachment = fixed/sliding/through; purpose = carrying/closure/decoration.

FORBIDDEN MUTATIONS
- 不新增、删除、复制或重新设计任何部件。
- [列出已验证的具体错误模式]

SCENE INVARIANTS
- 保留人物身份、身体比例、衣服、手指、背景、光线和水印。
- 姿势、手的位置、裁切和商品位置只按 scene_plan 中获准的调整执行，使产品始终在 presentation_envelope 内；其余场景保持不变。
- 只允许修改商品区域及形成真实遮挡所需的最小接触区域。

UNCERTAINTY
- 未被产品原图证明的区域保持不可见或不变，不得自行设计。
```

不要用“same bag”“保持一致”代替结构描述。也不要为了防错而添加未经证明的反向断言。

## 7. 单图验收

必须把候选图与产品原图并排，在原始分辨率检查，不只看缩略图。

每个可见或重绘的身份区域都必须在 `qa.landmark_records` 中有唯一 ID、原图来源、归一化裁图区域和逐项判定，覆盖所有高重要性事实与拓扑，包括手柄端点、扣件、翻盖、侧褶、开口、缝线、五金与底部（仅对有证据且实际可见的区域）。保存对应候选裁图或可复现比对记录；不能用一张全图的主观评价代替逐部件 QA。证据约束重建还必须用 `material_identity_fact_ids` 指定材质身份事实，并在 `qa.material_comparison` 逐项记录来源裁图和 `pass` / `fail`；纹理、粒面、光泽和硬挺度任何一项不符都不能被整体构图通过所覆盖。

在 `qa.protected_pixels` 记录所有受保护区域 ID 的实际比较结果。按已记录的确定性变换将来源对齐到候选，再检查应保留的产品像素；不能把允许的几何映射误当漂移，也不能放宽容差掩盖结构或纹理重绘。受保护像素变化即 `drift`，结果为 `rejected`。

### 产品身份

- 轮廓、长宽高比例、软硬程度和开口形态；
- 颜色、材质、反光、纹理、图案、压纹、缝线和拼接；
- logo、文字、五金的形状、数量、方向和位置；
- 口袋、翻盖、拉链、孔洞、扣件和底部结构；
- 每个承重、闭合和装饰组件的数量、路径、端点、连接方式与用途；
- 左右两侧和前后层级是否被错误镜像、补全或简化。

### 场景完整性

- 人物身份、脸、发型、身体比例、服装和手指数量；
- 经 `scene_plan` 明确调整后的姿势与构图，以及原背景、光线、色调和水印；
- 接触、遮挡、投影、尺度、透视和重力是否自然。

### 判定

- 任何高商业重要性项目不一致或受保护像素漂移：`rejected`。
- 任何需显示或重绘的关键部件无法确认、方法不支持或证据缺失：`blocked`，请求证据或更换方法。
- 草稿或 QA 未完成：`unverified_draft`；不代表可商业交付。
- 全部优先级检查通过后更新真实 QA 记录并在交付前再次运行验证器。像素复用方法申请 `verified_composite`；证据约束自然重建申请 `verified_reference_match`。`verified_reference_match` 只证明已登记的可见结构和材质通过参考对照，不证明像素相同，也不得称为 pixel-exact。只有通过验证的 `verified_composite` 才可称为 exact、faithful、commercial-ready 或等价的像素精确结果。

本协议中的 `PASS` 仅表示一次检查通过；历史 `REJECT` 对应交付 `rejected`，`UNRESOLVED` 对应需解决的 `blocked`。检查通过不会自行授予商业状态，质量修复后旧 `PASS` 失效。保存每次验证的命令、退出码和输出，不能只看 `valid: true` 而忽略有效交付状态。

“看起来合理”“与上一版一致”“用户可能看不出来”都不是通过条件。

## 8. 重试与整组复核

- 保存版本号，不覆盖上一候选。
- 每次重试记录一个具体偏差、对应证据和单一修正目标。
- 同一拓扑错误连续两次出现时停止提示词堆叠，重新检查事实表并更换方法。
- 第一张通过前不要批量生成剩余图片。
- 最后把整组并排，确认同一产品没有跨图改变组件数量、比例、材质、纹理、logo、五金或连接关系。
- 交付时说明哪些内容直接可见、哪些由用户确认、哪些仍未解决；不得虚假声称“完全一致”或使用了工具未公开的模型。
