# Reading Passes

## 1. Surface Pass
Find the entrypoints, module boundaries, configs, tests, and top-level docs. Stop once you can name the likely control surface.

## 2. Flow Pass
Choose the primary flow or the smallest set of important flows. State why they matter. Ignore side paths until the core path is clear.

## 3. Role Pass
Convert confusing names into responsibilities. For each important class, variable, config, or endpoint, answer: what job does it do in the flow?

## 4. Follow-Up Pass
If the user asks for more detail, expand only the requested branch. Do not restate the whole project unless the user changes the question.

## Questions To Ask Internally
- What is the one path everything else seems to orbit?
- Which names are role names, and which are just implementation details?
- What can be postponed without blocking understanding?
- What would a newcomer need before touching anything?
