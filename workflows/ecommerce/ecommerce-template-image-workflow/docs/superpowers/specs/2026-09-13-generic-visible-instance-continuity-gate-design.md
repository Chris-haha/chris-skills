# 通用可见部件实例连续性门禁设计

## 问题

第五张第四版右上特写中，棕色球柄只有银色套环残端，缺口内另有一截金属杆，两段之间没有连续结构。生成提示词已经声明它们属于同一把勺子，但最终画面仍然断裂，随后又被人工质检误判为通过。

根因不是缺少某一句“勺子不能断”的商品专用提示，而是工作流只有任务级语义约束，没有逐个检查画面中每一次部件出现。一个部件在中央、角标和特写中重复出现时，某一实例断裂不会被机器化的批准流程阻止；`brief.md` 也可被直接写成通过，缺少与具体图像、具体实例和局部证据绑定的正式门禁。

## 目标与边界

建立商品无关的“可见部件实例连续性”机制。它适用于勺杆、提带、电线、把手、拉链、铰链、支架、软管、鞋带、家具腿、首饰链及其他任何需要保持连续、连接或归属关系的结构。

核心代码不得包含杯子、勺子、小狗或当前项目名称。商品专属事实只存在于项目的 `product-identity.md` 和质检记录中。

门禁的目标不是保证生成模型永远不产生失败候选，而是保证断裂、错接、悬空或归属不明的候选不能被标记为通过、不能交付为当前成品，也不能解锁下一张图片。

## 可见实例契约

`ProductIdentity` 新增必填字段 `visible_component_instances: tuple[str, ...]`。Markdown 新增“可见部件实例”区块，CLI 新增可重复参数 `--visible-component-instance`。

每条记录采用通用格式：

```text
instance-id: 部件与所属主体；起点 → 连续段 → 连接件 → 终点；允许遮挡；支撑来源；禁止状态
```

`instance-id` 必须匹配 `[a-z0-9][a-z0-9-]*` 且在当前图片内唯一。冒号后的描述不能为空。加载和写入阶段必须拒绝缺失区块、空记录、非法 ID、重复 ID 或空描述。

同一种物理部件在画面中出现多次时，每一次出现都必须拥有独立实例 ID。局部摄影切片虽然不表示额外配件，但仍是需要单独验收的视觉实例。

## 生成提示词

直接提示词逐条输出可见实例契约，并增加通用规则：

- 每个实例独立追踪，其他实例正确不能抵消当前实例失败。
- 从起点到终点必须显示一个连续且归属唯一的结构；连接件两侧必须真实相接。
- 遮挡只能隐藏允许遮挡的连续中段；遮挡前后必须方向、粗细、材质和透视一致。
- 相切、靠近、叠放、阴影或语义关系不能冒充物理连接。
- 任何杆、线、带、链、把手或连接头出现断口、残端、两截错位、凭空终止、穿透或错误归属时，整张图片失败。

## 质检证据文件

每张候选图必须生成 `visual-qa.md`，并绑定一个明确的候选文件名。报告对产品清单中的每个实例包含：

```markdown
## instance-id
- 裁图: qa/instance-id.png
- 结果: pass
- 追踪: 对画面中实际可见连续路径的说明
```

裁图文件必须存在且非空；结果只能是 `pass` 或 `fail`；追踪说明不能为空。报告中的实例 ID 必须与产品清单完全一致，不能遗漏、增加或重复。任一实例为 `fail` 时，整份报告状态只能是 `failed`。

## 批准与下一张门禁

新增两个通用命令：

- `record-visual-qa`：接收候选图文件与每个实例的 `ID|crop-path|pass-or-fail|trace`，验证后写入 `visual-qa.md`，但不自动批准图片。
- `approve-image`：只在用户明确确认后调用；要求 `visual-qa.md` 绑定当前候选、实例集合完全一致、所有裁图存在且所有实例为 `pass`，然后把 `brief.md` 状态改为 `approved`。

准备下一张图片时，即使上一张 `brief.md` 被手工写成 `approved`，仍必须重新验证其 `visual-qa.md`。报告缺失、候选不匹配、实例缺失、裁图缺失或任一失败时，继续阻止下一张。

## 当前第五张回归案例

第五张至少登记三个勺子视觉实例：中央完整勺、右上合盖缺口中的勺、右下完整勺。右上实例必须能在同一裁图中连续追踪：杯内方向的金属杆 → 开放缺口 → 外侧连续金属杆 → 银色连接套 → 棕色球柄。套环残端与缺口内另一截金属杆之间存在任何可见断口都判失败。

重新生成时只使用模板和原始产品图。每个候选先裁出三个勺子实例并逐一验收；只有三处全部连续且其余产品事实、花纹、装配和支撑约束同时通过，才保存为新的当前成品并提交用户确认。

## 测试

采用 TDD 覆盖：实例格式解析、非法和重复 ID、Markdown 往返、CLI 输入、直接提示词、QA 报告精确实例集合、失败实例、缺失裁图、候选文件不匹配、无 QA 禁止批准、无 QA 禁止解锁下一张，以及完整通过路径。完整测试套件必须保持绿色。
