# 电商生图产品一致性锁设计

## 背景与根因

当前提示词生成器只要求模型保持产品的“外形、比例、材质、颜色、部件与可见细节”，但没有结构化记录部件数量、部件之间的连接关系、明确不存在的物件和仍待确认的歧义。

本次杯具任务中，参考图里的长勺由银色勺头、金属杆和棕色球形末端组成。因为部分角度里勺子横放在杯盖上，生成流程把棕色球形末端误判成杯盖上的独立摆件，并在画面下方又生成了一把完整长勺，造成部件拆分和数量重复。

## 目标

- 生图前必须建立结构化产品一致性清单。
- 清单必须表达部件名称、精确数量、连接关系、禁止出现的物件和不确定项。
- 存在未确认的不确定项时，不允许生成直接生图提示词，必须先向用户确认。
- 提示词必须逐项携带获批清单，禁止模型拆分、复制、合并或新增部件。
- 生成后必须按同一清单审查数量和连接关系；不一致的图片不能标记为通过。
- 保持当前模板匹配、逐张确认和两种生图渠道的现有行为不变。

## 方案选择

采用强制 `ProductIdentity` 清单与生成前验证门。仅增加通用提示词无法阻止代理先验识别错误；引入自动部件识别模型则会把同类歧义转移到另一个不可审计模型。结构化清单让用户能够直接确认事实，并为提示词和质检提供同一份权威来源。

## 数据模型

新增不可变数据类型 `ProductIdentity`：

- `components`：部件描述及精确数量，例如“1 把完整长勺”。
- `relationships`：部件连接或从属关系，例如“棕色球形末端固定连接在金属勺杆上”。
- `forbidden_inventions`：明确不存在、不得生成的内容，例如“杯盖上的第二个球形摆件”。
- `unknowns`：无法从参考图可靠确认的问题。
- `approved`：用户是否已确认该清单。

项目的当前图片任务目录保存 `product-identity.md`。Markdown 是用户可审阅记录，解析器只接受固定标题与列表格式，避免自由文本被误当成已确认事实。

## 命令与文件流程

新增命令：

```bash
python -m workflow.runner set-product-identity \
  --project puppy-mug-set-20260910 \
  --image 1 \
  --component "1 个杯子" \
  --component "1 个杯盖" \
  --component "1 个小狗造型盖钮" \
  --component "1 把完整长勺" \
  --relationship "小狗造型盖钮固定在杯盖上" \
  --relationship "长勺由银色勺头、金属杆和棕色球形末端组成，三者属于同一把勺子" \
  --forbid "独立的棕色球形摆件" \
  --approved
```

流程顺序：

1. `prepare-image` 继续负责模板选择和任务目录创建。
2. 代理检查所有产品参考图，写入 `product-identity.md`。
3. 若存在看不清、归属矛盾或功能未知的部件，写入 `unknowns` 并向用户逐项确认；此时不得标记 `approved`。
4. `write-web-handoff` 在构建提示词前加载清单。文件缺失、未批准或含未解决问题时立即失败，并输出可操作的确认提示。
5. `build_direct_image_prompt` 将部件、关系和禁止项分别放入“产品一致性硬约束”区块。
6. 两种生图渠道都使用同一份直接提示词，因此约束不会因渠道变化而丢失。
7. 生成后代理使用清单完成逐项视觉检查，再决定是否允许用户批准当前图片。

## 错误处理

- 缺少 `product-identity.md`：停止并提示先检查产品图、创建清单。
- `approved: false`：停止并提示等待用户确认。
- `unknowns` 非空：即使错误标为已批准也停止，列出必须确认的问题。
- 任一必填列表为空：拒绝解析，避免空清单绕过验证。
- 图片生成后出现数量、从属或连接关系偏差：保留失败图，强化受影响关系并仅重做当前图片。

## 本产品的权威一致性清单

### 部件及数量

- 1 个抹茶绿色陶瓷杯。
- 1 个焦糖棕色杯柄，属于杯体。
- 1 个焦糖棕色杯盖。
- 1 个戴红色项圈的小狗造型盖钮，固定在杯盖上。
- 1 把完整长勺；银色勺头、金属杆和棕色球形末端共同组成同一把勺子。

### 禁止项

- 不存在独立的棕色球形摆件。
- 杯盖上除小狗造型盖钮外，不得增加第二个摆件。
- 不得把勺子的棕色球形末端从勺杆上拆下。
- 不得复制出第二把勺子或第二个棕色球形末端。

## 测试设计

先写并观察以下测试失败，再实现最小代码：

1. `ProductIdentity` 可写入并从 `product-identity.md` 完整回读。
2. 缺少一致性清单时，`write-web-handoff` 被阻止。
3. 清单未批准时，`write-web-handoff` 被阻止。
4. 清单含 `unknowns` 时，`write-web-handoff` 被阻止并列出问题。
5. 已批准且无未知项的清单被注入直接提示词。
6. 生成提示词明确包含精确数量、部件关系、禁止新增、禁止拆分和禁止复制规则。
7. 现有模板匹配、展示文案、单图确认和网关测试全部继续通过。
