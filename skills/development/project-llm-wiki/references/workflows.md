# Wiki 工作流

项目任务的读取顺序、实际执行/验收、模板实例消费及各目录更新触发条件，见目标库的 `agent-workflow.md`；没有该页时参考 [通用运行流程](../assets/wiki/agent-workflow.md)，遵循既有 schema，不在普通查询时自动安装或迁移。本文细化摄入、查询、增量同步与体检，不替代实际开发/排障所需工具及项目验证。

## Ingest：来源 → 摘要 → 综合知识

先读目标 schema、index、sources 与可能相关的旧页。核对材料时间、版本、适用范围与读取能力；扫描范围不包括秘密或无关私有资料。PDF/Office 等不能读取时标记 pending，提出所需的文本导出，不要伪称已解析。

1. 在 sources 中为新来源分配稳定 ID，同一来源更新复用同一摘要；巨大集合按可核查的单元分组，记清文件清单与覆盖范围。仓库来源用相对路径加 commit/符号/行号，网页用 URL 与获取日期，讨论用经过用户提供或确认的持久材料。一次对话若需独立出处，可在授权范围内将脱敏结论保存到 raw，再入库。
2. 写 `summaries/` 来源摘要：材料是什么、有效版本、证据性质、要点、知识去向与缺口。尚未写入知识页的资料不能标为 ingested。
3. 合并进已有主题页；只有现有主题承载不了时才新建。domains/capabilities 放足以理解范围内主题的参考事实，entities/concepts 等跨来源综合，summary 保持摘要职责。非代码项目可用 domain 表达研究主题或产品领域，不必强造软件模块。
4. 在关键事实旁写可定位证据，区分确认事实、推断与历史状态。代码行为以当前代码/测试为主要证据，产品意图以已确认需求/决策为证据；观察到的行为不自动成为规范。冲突保留各方时间与范围，在 open-questions 登记，不能仅凭“更新日期较新”裁决。
5. 维护相关页面互链、updated、index 摘要及 sources 状态；append-only 追加 log。有未解问题则写清问题、影响、证据和下一步。
6. 原件留原地，不默认移动、删除或重写。raw 文件通过 sources 状态判断待摄入，完成摄入后无需归档搬移来消除告警。来源内容变化时重新核对；相同内容重复摄入不重复造页和日志，若做了新核验则记录核验结果。

来源状态：pending（未摄入）、partial（写入部分，列出缺口）、ingested（约定范围已写入对应知识页）、excluded（不摄入并说明理由）。这里的“约定范围”必须明确；索引一个路径不构成摄入。sources 中摘要必须存在，summary 的知识去向也必须是真实知识页。

## Query：问题 → index → 少量页面 → 证据

先读 index，定位 1–3 个相关页面，再按链接必要扩展；不要默认加载整个 Wiki。页面不足或日期/版本可疑时回查原始资料；涉及当前行为的问题需核对当前代码或验证结果。回答附可用 Wiki 路径与证据锚点，说明未确认或过时内容。

用户授权维护或项目已接入相关同步约定时，将有复用价值的新结论按 Ingest 回流；只读任务返回可应用的候选更新。纯查询未产生新知识时无需人为制造 query 日志。没有找到答案不等于没有相应实现。

## Update：变更 → 受影响知识 → 一致性

从变更文件、来源记录和原有 frontmatter sources 找受影响 summary 与知识页，再沿 related/正文链接检查直接依赖的概念、能力、实体、操作指南。无需无差别重写整库。

普通开发/修复任务在验证实际结果后做影响检查：规则不变而仅修复实现时保留规则正文，修正当前行为与旧缺陷状态；对象定义、模块职责未变则不修改这些页面。复用已有来源及摘要，不按每次请求新建一套知识页。任务实例与执行轨迹留在工作记录位置，只将经证据支持的事实、已确认决策或可复用教训入库。

修正失效事实，更新证据锚点和实质修改日期；保留仍有解释价值的决策历史并加状态补记，不能伪装过去没有发生。原件被移动/删除时记录旧位置及替代出处，不静默抹掉证据。更新 sources、index 与 log，新增未决冲突登记 open-questions。

目标库已有生成页面时，先查生成器和人工维护区的约定，通过原生成流程更新，不直接改会被覆盖的部分。无生成器的普通库不需引入生成基础设施。来源版本变化后，只有逐项复核过的范围才可宣称同步完成。

## Lint：结构检查 + 内容复核

```text
node "WIKI_ROOT/tools/wiki.mjs" lint --project-root "PROJECT_ROOT" --wiki-path "docs/wiki"
```

脚本只读，不自动修复文件，支持该技能模板生成的 schema：

- UTF-8/BOM、必要根文件、页面 type/真实日历日期/sources，业务方法页任务视角、领域页关联节。
- 普通行内 Markdown 链接（包括图片、尖括号路径）、引用式链接目标，忽略代码示例；相对目标需存在且留在库内。外部链接/页内 fragment 不验证可达性；不解析 HTML、嵌套括号或完整 CommonMark，也不检查 heading anchor 是否存在。
- index 对知识页覆盖、related 目标、append-only log 标题格式；检查规则无法证明历史日志从未被改动，需结合差异审查。
- sources 固定列顺序的表格、摘要路径、raw 待摄入状态、原始路径存在性与 Wiki sources 的来源登记。支持 frontmatter 简单标量、行内数组、缩进列表；带复杂 YAML 时人工检查或使用目标库原有解析器。
- 疑似凭证只报告文件与行号，不回显匹配值；扫描 raw 内文本，但不解析二进制附件。启发式有漏报/误报，不能以通过代替人工脱敏。

error 修复后再运行；warning 按证据处理并说明。现有库 schema 不同则用现有工具或人工核验，不能为了通过本脚本批量改库。需要新增页面类型/字段时同步 schema 与校验器；这属于结构演进。

自动检查后人工复核：读者是否能不打开原文就理解本次主题？摘要与参考页是否互相重复？证据支持结论吗？双向链接是否反映真实关系？规范是否越权升级？来源账本是否有假覆盖？凭证或个人信息是否已脱敏？

将实际检查范围、错误/警告数和未验证项追加 log。不要把结构检查通过表述为“事实全部正确”或“安全审计通过”。
