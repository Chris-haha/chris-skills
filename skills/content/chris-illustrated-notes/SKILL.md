# 写一篇能靠图推明白的笔记

先读用户的题目、材料和目标栏目的相邻文章。找出读者遇到的一个具体困难，以及读完后能独立做出的判断。例如，“能说出召回率的定义”不如“助手漏答还机时间时，能查出那条规定有没有送到模型手里”。保留已有原题、作者亲历和技术边界。资料不全时优先查原始记录、实现、论文或产品文档。

## 将参考方法转为原创内容

参考文章用于研究讲解深度、图文关系和解释技巧；不可沿用其问题清单、章节顺序、案例、比喻、段落推进、句式或配图构图。研究后关掉参考正文，依据目标项目的一手源码设计独立问题、案例和文章结构，再独立成稿。完成后逐章检查相近提问、连续概念组合与句子，发现明显重合就重设计；不能保证不存在侵权。技术术语和客观事实可以重合，但具体表达必须原创。

参考篇幅只用来判断展开是否充分，不作为照搬章节或凑字数的理由。源码长文应覆盖目标项目独有的设计决策、输入输出和失败边界，资料不足就标明。公开稿只引用实际使用的事实依据；本 Skill 及其配套材料不出现写法或画法参考对象的名称，作品结构、案例和画面均独立设计。

## 选一条读者能跟上的主线

- **面试单题。** 找一句表面上正确、再追问一步就答不下去的话。在前面给能直接说出口的短答，然后把其中最容易含糊的动作展开。比如模型说“已退款”，后端可能已经退款、执行失败或尚未收到请求。给读者可查的记录，让他分清这几种情况。最后换一个条件，让读者自己判断。对话只有在双方真有分歧时才有用。
- **概念或源码长文。** 固定一次输入，沿着实际的调用、数据或状态往下走。每次跨层，交代上一步交出了什么、下一步谁接、哪种返回值会改变走向。先走通正常路径，再把故障插到两个具体动作之间。职责示意表达组件的分工，时序示意表达这一轮谁先行动；给读者辨认二者的线索。
- **工具实践或对照。** 先给读者看一项可观察的结果。要比较，固定任务、样例和其他重要条件，再从操作记录里找分歧发生在哪个决定。真正的成品、报错或设置位置用实际截图。仅有操作说明时写为演示，只有真实执行过才给实测结论。
- **工程选型或研究解读。** 选一个会改变正确判断的条件。如更换提问者的地区、把关键证据移到另一位置，重新推一次。说明结论来自论文实验、作者实测、实现约定还是教学假设。类比后回到实际对象；费用、性能、版本默认值需要各自的一手依据。

刚引入一个术语，就用当前例子解释它负责哪一步。数字给出分母和单位，代码前摆输入，代码后走一遍具体输出。多节长文可以沿用同一份资料、同一请求或产物；查阅型文章按读者要找的任务分节。标题要让隔天回来的人找到当时卡住的位置。

源码长文先找原项目的实际入口、关键实现与版本，留出可点击的固定版本来源。把“源码确认”“文档约定”“教学假设”和“亲自实测”分开；一次假设的工具调用不能写成已发生的运行结果。先画整体职责，再追一条具体输入，沿途交代数据、调用方向、失败分支和停止条件；只展开对读者理解有用的模块，不照搬参考文章的组件清单。

## 在难点处安排 GPT Image 插画

**本 Skill 的原创教学插画使用 GPT Image 实际出图。** 调用当前环境的图像生成入口（Codex 中使用 imagegen），保存栅格成品并打开核验。用户指定具体版本时核实可用接口；工具没有回传具体版本就只记录实际入口。生成失败时保留已写好的正文和画面说明，如实标出缺图；禁止把 SVG、Mermaid、HTML/CSS 卡片、手工表格或提示词占位作为插画交付。公式、数据表与代码仍可以用原生文本供读者验算。操作截图来自实际界面。

先用一句话写清读者看完这幅图能做什么，例如“指出是哪一份材料没有交到下一步”。把这句话变成画面里可指认的差异。按当前小节选画法，同篇可以换画法。画面说明写清要留下的条件、会动的物件、阅读方向和少量必须准确的字。

### 先设计每张正文图，再决定怎么画

逐节寻找真正需要可视化的难点，而不是按固定字数、标题数量或凑满组图决定配图。生成前为每张图留下简短画面单：①正文位置与读者问题；②必须可见的事实、动作和因果／对照关系；③选择场景、剖面、前后对照、路径、时间轴等画法的理由；④主体的合理颜色、必须区分的状态、自然留白，以及不应出现的元素；⑤必要文字与逐项事实依据。写清类比中每个关键物件对应什么，避免只画灯泡、齿轮等泛化装饰。没有具体动作或关系的配图，先重想画面。

**把画面单写成可执行的设计，而非关键词罗列。** 先用一句话回答“谁对什么做了什么，造成什么变化”；再选择最容易辨认这一变化的主物件、空间关系和视角。对比至少写清不变条件和造成差异的那个条件；步骤图写清前后及分支；涉及不确定状态的图明确哪些是可能结果。优先让物件的形态、位置和动作表达逻辑，文字只保留识别对象和关系所需的短标签。类比如果掩盖了技术边界，就换更直观的示意，不强行添加人物或生活道具。

**把整体画法拆开决策。** 位置、教学目的、画面结构、线条质感和颜色分配分别由内容决定；图的结构可以是单一动作、局部系统、对照、剖面或时间线，风格连贯不等于物件、构图和色板一律相同。生成前写出标题遮住后的第一眼判断与一项容易误读的失败信号。复杂关系拆图或让正文解释，不为了每图只剩一个物件而丢失必要条件，也不把正文缩成整段写在图里。

**信息密度要足以解释机制。** 从原文提炼读者需要推导的主体、输入、处理、条件、分支和输出，按该小节实际内容取舍，而不是把“一张图一个重点”误解成只能画一个动作、两三个标签或三个名词。一张图可以包含同一核心机制中的多步、分叉和短句；依赖关系用线或空间关系清楚表示，图中应能回答“谁做了什么、条件是什么、结果流向哪里”。图位是知识补充，不是为正文加气氛。遮住小标题后仍只看见道具或几个名词，说明信息不足；出现挤成整段文字或箭头交叉，再拆解或简化。手机缩小检查字的实际可读性，而不是无条件删掉必要信息。

**颜色要清晰、有精神，也必须有理由。** 对象可以采用可信自然色，但不要因为想让画面丰富，就给每个平级条目、步骤、名词和容器分配不同颜色。先用位置、文字、箭头、线型和对齐表达顺序、对应与包含；只在确实有利于追踪同一对象、区分容易混淆的路径／状态、指出风险或强调关键变化时赋予语义色。平级条目若无需要区分的差异，保持同等视觉权重，不靠颜色制造层级。

**避免重复强调。** 同一个重点不需要同时给标题、文字、整行底色、边框、图标和装饰线涂同一强调色；选择最有助于理解的承载位置，其他元素保持易读。生成前写出“这处颜色让读者多看懂了什么”，生成后遮掉每处装饰性色块检查关系是否发生改变；只为填满画面、制造统一风格、循环换色或衬托标题的颜色应删减。不要把这一条误读成整图只准黑白灰或固定一种点缀色，自然物件仍可有合理颜色。

**用户认可的用色实例：** 请求托盘本体带适度颜色，其中“系统指令”“消息历史”“工具定义”等平级内容统一用白底黑字，借助物件、文字和位置表达包含关系；不为每张内容单独上色。这里可借鉴的是物件着色与平级信息处理方式，不是把蓝色托盘或该构图固定为后续模板。其他主题仍按物件与信息需要决定颜色。

**红色不作配图主体或主色。** 不用红色大面积填充主要物件、画面背景或占主导的构图元素；仅在确有必要时小面积用于警示、错误或特定信息的强调。不能因为禁用红色主体就把每张图统一成另一种固定配色，仍依据对象、关系和具体画面决定其他颜色。

控制大面积色块与高饱和强调，不默认将所有颜色混灰、染成复古纸色或降低对比度。允许清亮、适度饱和的彩色，有明暗对比但不荧光；颜色不能是区分关系的唯一线索。逐图检查是否存在语义不足的分色或反复渲染同一色；并排检查是否显脏、暗沉、褪色或所有图重复同一配色。常见绿、红含义按具体场景决定，不机械固定。

考虑可辨识的真实物件、谁操作谁及发生的变化；物件、人物仅在帮助解释时出现。流程有分支就明确箭头起点和终点；对比要固定共同条件；记录与模型输入是不同东西时画清两者关系。资料不足以确定某个动作或技术路径时，不将它画成事实，图注交代示意边界。

为每张图独立写颜色分配：哪些物体保持可信材质色、哪些颜色跟随同一对象、哪些局部确实需要突出。先画面后色彩，允许几幅图自然出现不同的色彩比例，也允许有理由地重复同一对象的颜色；不按组图轮换色板，不把所有画布、装置、箭头都染成相同蓝绿灰。避免单图出现互抢的鲜艳色；如果压低饱和度会丢失重点，调整色块面积与层级，而不是一律灰化。缩成文章宽度后检查重点是否仍能被看见。

独立判断配图位置、教学目的、结构与色彩；从内容关系选择物件和动作，并事先写出可能误读的地方。不沿用固定角色、母版布局或整篇配色；未经核对，不宣称生图结果技术正确。

| 读者卡在哪里 | 画面怎样回答 |
| --- | --- |
| 没见过这个机制 | 找一个动作同构的生活场景。例如从架上按书脊找书，再拿出整本。画清谁在找、什么时候取、取了什么。回到技术对象时，指出类比的边界。 |
| 两种情况看起来都成功或都失败 | 固定同一输入、顺序、对象与尺度，并排或上下对齐，只改导致分歧的条件。让读者先指出变化，再揭晓结果。 |
| 想知道是谁先动、并发省在哪儿、失败后回到哪一步 | 有来回就按参与者分列；有等待或重叠就用共用时间轴；有重试就把返回线接回实际恢复点。用标签、实虚线或端点说明请求与返回。 |
| 分不清包含关系、作用范围或信息边界 | 用嵌套、层次、书架或展开剖面。读者应该能圈出“谁持有它”“当前能看见哪部分”。随时间变化的量另用时序或数据图。 |
| 问的是差多少、在何处转折、分数为何变化 | 保留可验算的分母、坐标、单位或同尺度长度；必要时在正文给出原始数值。示意趋势在题注中说明。 |
| 想确认按钮位置、命令是否生效或故障发生在哪一环 | 实操用真实截图或录屏，保留输入、关键回显与少量上下文。定位故障时对齐同一次请求的相邻记录，圈出第一次不一致。虚构教学样例清楚标为演示，可画成校对稿；别把生成的画面写成实测。 |

**同篇换构图时，保留同一本讲义的手感。** 不强制每张图复用角色、器材、构图或参考首图；只有需要跟踪同一对象时才保持可辨认的身份。先判断这一节是需要看动作、对齐条件、观察时间、确认边界，还是需要真实证据；若图删掉后正文已经能轻松解释，就不要为了凑数加图。 生成前检查读者第一眼看哪里、两种情况靠什么对齐，以及哪些标注能让人看懂动作。确需追踪同一角色或物件时，点名需要沿用的外观与标记；线条、字形或批注只在服务阅读时沿用。本节需要用颜色认出哪些对象、看见哪处变化，另写一句。人物出现时给它一个影响理解的动作，例如指住平顶或调低重拍。曲线或实录自己就能讲清的地方，把面积让给证据。对照题要让读者用手指出哪一步不同、哪里能看见后果。如果读者只能认出设备名称，就重画发生变化的地方。

**颜色先贴合物件和信息，再决定视觉强调。** 用户否决单图堆叠鲜艳色，也否决把整篇一律调成灰紫、灰绿、灰红等轮换色板。先区分画面类型：生活场景中的人、电脑、纸张、工具等参考现实中可信的外观和材质；示意图中同一对象、路线或状态可用色彩编码，但先想清楚每种颜色帮助区分什么。物体不必为了好看而逐件变色，绿植也只在场景确有需要时出现。以白色或中性色留出呼吸，限制争抢的色相和高饱和面积，必要时用小面积强调；灰淡不是硬性目标，也不要为避免重复强行换色。形状、位置、线型和标签共同承担区分任务。永久禁色仍然优先：不能为了还原物体本色使用橙、橘、黄、金或琥珀色主色或强调，也不使用暖黄背景与光照。


Chris 博客永久禁色：插画不使用橙、橘、黄、金、琥珀色主配色或强调，也不用暖黄底、暖黄光或渐变。禁止将禁色误解为只能使用灰色或某一种强调色；换一节就重新依据对象和动作分配颜色。使用原创构图与角色，右下署名“不吃辣的Chris”。

本篇示例提示词：“画相机借还检索的下一幕。同一张桌上，左右各有一张①校园卡，它的图案和颜色与上一幅一致。木柄印章在两边都盖下‘已命中’。右边的手把带红页签的还机规定④放进左侧对应的空位。左下‘找回 1/2’，右下‘找回 2/2’。把两幅图并排看，读者能顺着同一个页签找到刚刚补回的证据。”红页签是这本借还手册里的道具，别的选题按自己的材料决定怎样突出变化。

## 把图放回它解释的那一句

读者需要先认识全局时，先放总图，然后用一个具体输入走其中一段。读者困在某个误判时，先给场景和问题，再放图。图后指出一个值得看的细节，以及这个细节怎样改变判断；别把图中文字依次念一遍。替代文本写明主要关系，使图片加载失败时也读得通。段落长短跟着推理走，小标题与站内目录配合。

按目标博客的 AGENTS.md、设计规范和现有 frontmatter 接入；Agent 面试单题另读该栏写作规范和题单。项目图解规范可补充术语、水印与手机验收，本 Skill 的生成方式按上文执行。新增图片使用本地资源，入口放在读者会遇到这个问题的位置。

## 交稿验收

1. 从开头的问题走到答案，检查谁在行动、信息从哪来、一步怎样影响下一步。遮住答案换一个条件，重新推导并核对依据。示例数字、代码输出、正文和图要能互相对上。
2. **逐张打开生成成品。** 先画一份“谁 → 谁、传递什么、什么条件发生”的事实清单，对每一根箭头逐条核对正文和一手依据；不能因参考图也这样画就跳过核验（示意图的方向也可能与文字或源码不一致）。 检查汉字、序号、时间、数量、主体、动作、方向和署名。尤其看有没有多一件物体、时钟与数字互相矛盾、两幅对照偷偷改变了第二个条件。影响理解的瑕疵要改图，再打开检查。
3. 按正文顺序并排缩小所有图，逐幅指出对象、各色含义和视觉重点。单图若色相太多、高饱和色互相竞争或亮色装饰抢走注意力，先减少颜色、降低饱和度，再检查必要的状态对比仍可辨认；不要为制造变化而增加颜色。连续图若总是同一套颜色、人物和构图，应重新设计问题对应的对象与用色，而不是仅循环换色。遮住标题，看能否凭画面指出关键动作。同一数据系列跨图仍须认得出来。
4. 构建后从真实入口打开文章，在桌面和手机查看全文与每张图，复查亮暗显示。手机直接辨认不出教学信息时减少标签、换构图或拆图。向用户交付预览、正文和实际图件，并说明所用生成入口和验证情况。

需要选择画法、整理信息层次或检查常见误读时，查[教学图解设计要点](references/visual-methods.md)。
