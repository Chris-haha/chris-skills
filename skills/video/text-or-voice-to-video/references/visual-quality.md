# 成片视觉质量：禁用占位物，先设计关系，再画线

本文件用于每次分镜、组件实现和正式导出。它约束未来所有视频，不是只修补某一片的坐标。音轨同步、素材存在、类型检查通过均不能代替视觉验收。

## 禁止的默认表达

- 不以圆头、天线、眼睛和笑脸组成的机器人／Bot图标代指AI。也不换成灯泡、齿轮、芯片或另一套通用小图标来继续填空。原声谈AI时，可展示具体提问纸条、实际结果、目标实物、真实界面或统一人物正在做的事。
- 不把每句话自动变成“图标＋标签＋白卡”，再用连线串起来。分类与比较优先用清晰的空间分组、同一对象前后变化、一个具体情境中的对照；本技能不默认使用一源多分类的树状分叉图。
- 不为填满版面画短横线、悬空曲线、下划线式连接或没有端点的椭圆。说不清“谁以什么方向对谁发生什么”时，删除关系线，重新设计画面。
- 不用漂浮在卡片边角的红色圆圈叉、全局坐标放置的勾叉代表结论。状态属于具体对象，应该在对象内部预留的位置显示有意义的文字，例如“参数待核对”“需要补充依据”“符合已定义条件”。不把“AI可能犯错”直接画成未经说明的某个选项必然错误。

SVG和React可以绘制有具体内容的实物、场景、准确数据结构与机制。禁用的是通用占位语言，不是把问题换成另一种渲染技术。

## 每幕先选表达，再选运动

在 `storyboard.json` 的每个shot写 `layoutIntent`：`scene`、`flow`、`comparison`、`classification` 或 `transformation`。这是当前内容的表达目的，不能为了绕过检查把分类改名为流程。

先确认视觉主角和变化：例如“同一张购物清单补齐目标和数量后再交给采购者”，比“AI → 三个答案”更能解释问题。recipe只负责执行运动，不决定版式和叙事。需要的场景素材尚未完成时，不用演示节点代替最终画面。

画面分成稳定的标题区、主体区、字幕区。主体可以有空间变化，但标题、说明与字幕不可互相争夺位置。统一主次、对齐、间距、字体尺度，先完成密集状态，再设计进入与退出。

## 关系线契约

仅在存在真实关系时使用 `SemanticConnector`（`RelationTrace`现为同一实现）：

- `relationship="flow"` 用于移动、传递、因果或先后步骤，必须有可见箭头，随线条绘制推进显示方向。
- `relationship="association"` 仅用于明确的无向关联，例如书本与读者记录；仍须具体说明关系。它不是把分类线改名后重新放行的后门。
- `source`、`target`绑定具体对象ID、相同布局数据中的矩形和明确端口；从对象轮廓外留短间隙起止，不能从文字中心发出，也不能悬在空白处。
- 用`via`明确规划通道，避开所有说明文字、状态区和无关对象。新增文本、改变字体或调整布局后重新审计，不能只看旧坐标“应该没问题”。
- 循环必须有两个可理解的方向和两个具体端点，去向与返回分别绕开文字。用两条弧线圈住一段文字不表示循环。
- 分类、比较不画流程线；一个来源同时分出多条分类支线会被审计拒绝。需要复杂真实系统结构时先寻找实际界面／实证图，再设计适合该内容的画面，不能回退到默认AI图标分叉模板。

## 技术机制图与比喻的对应

讲解某个技术对象时，检查“去掉字幕后，主图能否辨认出这个对象”。神经网络的参数讲解优先保留层、节点、加权连接、输入表示与输出候选；不能只画调音台或机器旋钮，再用一行字称它为神经网络。面向小白可以简化节点数、突出一条连接，并明确教学示意及与实际模型的差异。可爱人物负责观察、指向或辅助操作，不抢占真正的机制图。

当画面展示“参数更新→预测变化→误差变化”时，用同一组计算结果驱动，至少验证更新前后预测、概率归一化及误差的含义。不要把物体从错误标签切换到正确标签冒充训练，也不要暗示一次更新必定答对。区分训练与普通推理：参数更新只在训练段发生；生成段通常固定已学权重，变化的是上下文、激活与候选输出，不能用持续调权动画暗示每次回答都重新训练。

真实数学网络中的多条加权边是模型本身的拓扑，不是分类伪流程。可在具体网络对象内部绘制，并保留节点/边身份、端点坐标和权重来源；不能借网络名称包装无依据的放射状图标。这样的内部图不冒充已经由 SemanticConnector 检查全部数学语义，需另做拓扑/数值检查及实际看图，保留 composition 根部审计。注释文字与路径使用独立预留区域。

## 可测量的场景组件

新工程的 `Root.tsx` 已在**整个composition根部、所有Sequence之外**安装 `AuditComposition`。保留这层，它记录全局帧号并覆盖标题、字幕和场景内外的所有可见内容。不要把它挪到局部节点中或删除。

从`src/visual/Visual`导入：

- `AuditScene`：标记当前场景，可在Sequence中使用；它不自行产生局部帧审计。
- `VisualObject`：声明实际对象ID、具体kind与用于布局的box；人物、实物插画、真实截图和自绘SVG都放在对应对象内。禁止使用`bot`、`robot`或`generic-ai`占位类别。
- `VisualText`：为文案提供稳定标签ID。审计还会读取未标注文字的实际浏览器文字矩形；同一标签中的重叠span也会被拒绝。
- `SemanticConnector`：从共享对象布局生成端点，传入ID、flow/association、关系意义与实际帧锚点。原来的裸`path`接口已移除。
- `StatusLabel`：放在所属对象内部的正常布局流，预留状态行／栏；传入明确owner、状态与短标签。它没有全局悬浮红叉坐标。
- `VisualDecoration`：只用于背景或标题／页脚分隔；不能把主体中间的无含义横线标作装饰来绕过检查。

```tsx
const sourceBox:[number,number,number,number]=[140,350,470,280];
const targetBox:[number,number,number,number]=[1210,350,500,280];
<VisualObject id="purchase-list" kind="shopping-list" box={sourceBox}>
  {/* 真实清单内容／对应实物，不是任意图标 */}
</VisualObject>
<VisualObject id="receiver" kind="purchase-inbox" box={targetBox}>
  {/* 预留内部状态行与说明区 */}
</VisualObject>
<SemanticConnector id="deliver-list" frame={f} at={event.frame}
  duration={event.durationFrames} relationship="flow"
  meaning="把这张清单交给采购者"
  source={{id:'purchase-list',box:sourceBox,port:'right'}}
  target={{id:'receiver',box:targetBox,port:'left'}}/>
```

## 导出前的阻断检查

1. 按真实口播实现专用场景，保留根部审计。starter的`VisualFilm.tsx`只显示“画面尚未设计”，不能再自动从subject生成可交付的节点模板。
2. 运行 `node render.mjs audit`。它自动渲染每幕开头、中部、落定，以及每个事件起点、中间、终点的静帧；保存实际DOM测量、PNG哈希和源文件指纹到`out/visual-audit/COMPOSITION_ID-report.json`。audit只检查视觉，不替代音轨验证。
3. 处理所有结构错误：机器人占位、缺少箭头、线压字、无对象归属的图形、端点悬空、状态越界／压字、文字互相重叠、越界、无意义细线、分类分叉。审计等待当前帧的其他delayRender、图片和字体加载完成后再测量，避免拿加载前布局冒充最终画面。
4. **Codex实际查看全部采样图**，包括每个事件的中间与落定画面；在原尺寸确认遮挡和细节，再看缩小后的主次与可读性，复查动作连续帧／正常速度。确认对象不是替换后的通用占位图、每条线确实有意义、分类不是演示白卡堆叠、状态文字和视觉结论准确。不能只看开场三张或只看末帧。
5. 由执行任务的Codex保存`visual-review.json`，不要求用户为例行验收另行批准。用当前report文件的真实SHA256填写`auditSha256`；在`checks`中明确完成`noGenericAiMascots`、`relationshipsHaveMeaning`、`noUnwantedOverlaps`、`badgePlacement`、`readableHierarchy`；逐scene记录`decision: "pass"`、**全部该幕已审计帧号**及具体所见`reason`。不存在未处理问题才可标pass，不能由脚本自动勾选代替看图。
6. 运行 `node render.mjs render`。没有当前审计和视觉复核、复核漏事件、图像被替换、源码／素材变化、结构错误时会拒绝正式导出。完整渲染还会检查**每一帧**实际布局，只有全帧检查通过才把候选文件变为`out/silent.mp4`。
7. 对最终成片继续进行音轨验证及观看；QA报告分别记录结构审计、实际视觉复核、全帧覆盖与声音测量。任何检查失败时，候选或旧版视频都不能作为本次合格交付。

横／竖版分别运行审计和复核；某一composition的通过记录不能认证另一个比例。修改画面后重新审计，不把旧通过记录复制给新源码。

已有工程再次改稿时，先备份并同步新版src/visual、visual-audit.mjs与render.mjs，将AuditComposition接到该工程原有composition根部；保留原专用组件、音轨、字幕和素材，不用starter占位文件覆盖它们。给分镜补layoutIntent、给实际对象补语义边界，再运行同一审计。未升级的旧导出入口不能认证后续交付，也不通过手工调用底层renderer跳过质量流程。

## 自动检查的边界

结构审计负责实际DOM文字矩形、可见SVG关系路径与对象边界，不是对生成图片内部的OCR、插画审美或任意自定义代码语义进行万能识别。原始PNG/视频中的机器人、图标模板感、文案事实和视觉主次仍由逐幕实际看图复核承担；不能把对象kind改名或套上容器就声称已通过审美检查。未来新出现的同类缺陷应补充可复现用例，而不是仅加一句“注意美观”。

文字裁剪支持实际overflow和inset()区域；其他文字遮罩必须先实现对应的可见区域测量，不能忽略检查。CompareWipe使用互补裁剪，StateChange先淡出旧文案再淡入新文案，避免把两层不同文字叠在一起。裁剪不是容许无意文字缺失的理由，仍须看图确认可读性。
