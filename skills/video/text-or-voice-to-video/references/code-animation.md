# 按效果选代码动画与混合镜头

本技能默认以Remotion合成整片，按实际旁白定位字幕与事件。下列为选型和接入指导，starter没有内置全部引擎、自动视频反推器或视频生成接口。检查实际依赖、工具和服务后再决定路线，不一次安装全部工具。

## 从理解目标选工具

| 需要的画面 | 优先考虑 | 使用边界 |
|---|---|---|
| 同一实物移动、请求走路径、精确计数、地图路线生长、插画分层出现 | React／SVG；大量笔画或粒子时考虑Canvas 2D | 数值、坐标与对象身份来自同一份语义数据。分层需要真实图层或矢量对象，不能把整张图的推拉称为逐层生长。 |
| 手绘草图、粉笔轮廓、一笔一笔画线 | SVG路径揭示＋Rough.js质感 | Rough.js生成手绘几何，不自动生成正确书写顺序。文字、汉字和公式的笔顺需另外准备路径或选择适合的专用工具。 |
| 可爱小人、火柴人或手绘人物实际开窗、搬运、拼装、调节对象 | 可编辑SVG／Canvas分层角色与关节姿态，按帧求解动作和接触点 | 先按[人物动作叙事](character-staging.md)设计动作与结果。手绘描边只提供质感，不能用整张贴图位移、缩放或循环眨眼冒充任务动作。 |
| 水彩、水墨、自然笔触、生成式绘画 | p5.js＋p5.brush；轻量效果可用已有纹理和遮罩 | 笔触风格不保证角色连续性；固定随机种子并验证可重现渲染。不要为普通箭头引入水彩引擎。 |
| 产品转台、可控相机、空间关系 | Three.js／React Three Fiber | 有模型与材质来源才谈外观忠实；缺少3D模型时先评估矢量或2.5D分层是否足够。 |
| 多步骤公式推导、几何构造、数学对象变换 | Manim，复杂度不足时用SVG／React | 数学段可以独立渲染后接回主片，截图、字幕与其他场景继续交给Remotion。不为一行算式迁移整片。 |
| 黏土材质、建模、复杂灯光、离线3D场景 | Blender | 材质、光照和动作需要实际制作；“用Blender”不自动获得黏土效果。保留场景文件、资源及可重渲染命令。 |
| 精确品牌文案、界面与卖点的产品镜头 | 实际截图／录屏＋Remotion／SVG | 建立明确风格板和每屏重点；示意界面标明示意，不把生成图当实际功能。 |
| 连续人物动作、穿门进入另一种画风、复杂自然表演 | 优先评估可实现的代码合成；必要时用局部视频生成 | 仅把适合生成的片段交给视频模型。准确文字、计数和机制留在代码层；不因为一个转场改用整片文生视频。 |

这些是优先级而非硬性绑定。同一作品可以混用，但每增加一种引擎都应解决一个明确的视觉问题。纯音乐MV不属于现有旁白对齐starter已验证的交付能力；需要单独的音乐时间线与验收，不能拿合成字幕时间冒充歌词对齐。

## 写稿到机制，而非每句一张卡片

只有主题时，先明确观众要学会回答的一个问题。科普通常适合“具体情境→对象与规则→持续演示→准确名称／公式→类比的限制”。不机械套顺序或强求一个类比贯穿所有题材；新术语过多时删减旁枝。

类比需要给出真实对应关系及失效处。例如缓存可以类比手边的小书架，但缓存命中率数的是查找请求，不能拿“十本书里八本在书架”冒充“十次查找八次命中”。计算示例用真实序列驱动图形、计数器与结论；区分示意数字与实测数据。先让观众看见规则，再给术语，避免开场堆定义。

写稿时只估时；稿件若需用户先审，展示完整可读稿，并明确当前未配音或渲染。不以“先生成一版试试”为由跳过用户的审稿节点。可独立完成事实核对与文字版视觉方向。

## 把美术描述变成可执行约束

在素材前保存项目的animation-plan.md：

- 受众、要理解的机制、目标时长与实际音轨状态；宣传内容还写明预期行动。
- 有来源的品牌资料，以及具体背景、主辅色、字体层级、轮廓／材质、光源、留白、字幕区和阅读停留。
- 各shot的对象、起始状态、动作、结果状态、渲染工具及选择理由，区分“计划／试制通过／正式接入”。
- 人物参与的shot还写明角色、身体部位、接触对象、动作阶段和造成的结果。`VisualObject`只约束语义与边界；需要实物、纸片、窗户或人物时，按其轮廓绘制，不自动套一层可见卡片。
- 转场前后保留的对象、运动方向、相机位置或形状，以及旁白语义锚点；若用拍点，另记实际音乐时间与来源。

例如“纯白背景、黑色文本、玻璃感产品界面、每屏一个可验证卖点、产品照片保持原比例”，比“高级科技感”更能执行；这只是产品片的一种风格，不是全题材默认皮肤。优先验证最能代表风格与机制的一个短镜头；这个内部验证不额外要求用户确认。

animation-plan是制作说明，不是新schema。storyboard v2的media仍为illustration／screen／diagram／type，recipe仍为现有八项；按实际画面分类。编译器不会因为写了renderer、transition或action就自动生成动画，专用组件必须实际消费每个event。

人物表演先选一个能看清接触和状态变化的短镜头验证，例如“小人走近窗户、手抓住把手、推开窗扇、松手后窗扇保持打开”。看连续帧与正常速度，确认身体和对象实际配合后再扩展整片。仅有动作名称、人物素材、引擎选型表或自动排版通过记录，均不证明人物动作已经实现；详见[character-staging.md](character-staging.md)。

## 外部引擎接回同一条时间线

先选择直接在Remotion渲染，或离线输出后导入：

1. **直接渲染**：所有状态由帧号或明确的时间函数求出。同一帧多次渲染及乱序seek应一致，不依赖墙上时间、后台requestAnimationFrame、未固定随机数或必须先播放前帧的累积状态。Rough.js固定seed；Three.js使用与Remotion帧同步的更新方式。p5／粒子／模拟若必须累积，预计算状态或离线按固定步长顺序输出，不能让并行渲染碰运气。
2. **离线输出**：保留Manim／Blender／p5等源代码、场景和输入素材；记录实际版本、入口、命令、seed、相机、帧率、尺寸、帧数、颜色和透明通道处理。需要透明叠加时用实际支持透明的格式或PNG序列，并检查合成后的边缘，不能假设普通H.264 MP4带透明。
3. **检查导入素材**：用实际探测结果确认分辨率、帧率、时长、首尾帧、透明度及音轨。按主片fps输出或明确转换，不用拉伸整个片段强行赶上旁白。无声音效需求的外部画面不带入其背景音乐；正式旁白仍是主音轨。
4. **定位语义**：外部片段中哪个局部帧对应哪个动作，记录在animation-plan；把这些动作映射回实际caption/event。改旁白后重算锚点，必要时重渲染片段，不只挪字幕。
5. **登记与复核**：输出放public并登记assets.json，项目自制渲染如实记project与源文件来源；模型生成片段如实记generated、prompt、尝试次数及实际服务信息。资产存在不代表正确，接回后仍逐幕实际看图与正常速度看运动。

Canvas／WebGL／外部视频内部的字、路径和状态不受DOM测量完整覆盖。准确标签优先保留在可测量的文字层；外部对象用VisualObject管理实际边界并保留AuditComposition。不能把包含复杂关系和文字的整幕装进一个框就声称逐项测量已通过。QA明确哪些内容由结构审计测量、哪些由看图复核；任何新增自动检查能力必须实际实现并验证。

## 语义、音乐与转场

旁白驱动的讲解仍以当前音轨为唯一时钟。先对齐句子与关键动作，再参考真实音乐的拍点安排可调整的镜头切换、背景运动或装饰。不要为了卡拍提前给出答案、打断一句话、加速原声或压缩阅读停留；不合适时换拍点、调整音乐片段或放弃该处卡拍。音乐来源、混音、响度与验证仍遵循[audio.md](audio.md)，不是添加一个BPM数值就算完成音乐同步。

跨场景优先延续对象：请求纸条变成记录条目、书架轮廓变成缓存区域、同一条路线跟随讲解推进。镜头运动要服务机制，穿门、遮挡和形状匹配只有在动作与构图连贯时才成立。

局部视频生成可先制作起止构图和连续动作要求，记录角色、服装、光源、运动方向、镜头速度；实际可用的模型若支持首尾帧，再按其能力调用。生成后检查对象身份、形变、接点和帧率，准确字幕／Logo后叠。缺少接口、权限或可接受结果时，报告限制并采用可实现的代码转场，不声称已经实现连续穿越。不把教程出现的模型名、版本、价格或开源项目当作当前已验证事实。

## 实现依据
