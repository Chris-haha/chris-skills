# Output Contract

## Default Shape
Return a compact answer in this order:
1. one-sentence summary
2. main flow
3. key modules or actors
4. glossary of names to roles
5. what not to read yet
6. next drill-down target

## Anti-Noise Rules
- Do not repeat the same explanation in multiple sections.
- Do not expand untouched branches.
- Do not restate the whole project on every follow-up.
- Do not dump every variable name unless it helps the flow.
- Do not write long background paragraphs when a short structural note is enough.

## Good Compression
- Use tables for name-to-role mapping.
- Collapse repeated details into one line.
- Prefer labels like "responsible for", "routes", "stores", and "guards".
- If uncertain, mark the uncertainty and move on.

## Follow-Up Discipline
When the user asks a narrower question, answer only that branch and anchor it back to the existing map. If the new detail would not change the main flow, keep it short.
