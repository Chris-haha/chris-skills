# 分层输出模板

模板服从信息状态，不固定输出六段。简单问答简短回答；每轮只问一个必要问题。

## A. 资格待确认

- 已知：届别/身份/户籍学籍等用户提供的事实。
- 缺口：影响哪条路径，为什么不能据此推荐学校。
- 可推进：解释相关制度、官方核实入口或学校公开信息。
- 下一问：一个最影响可报范围的问题。

不填个人冲稳保表，不给排序，不将用户点名学校包装成可报推荐。

## B. 规划预案

- 当前可报范围与依据；未确认路径单独列出。
- 成绩记录及口径，明确“二模预案”“估分预案”等。
- 筛选条件、条件化备选池；每项列当届计划是否已核验、待核前提和定位局限。
- 后续需要补充的证据与下一步。

当届资格规则未确认时使用 A，不因其他个人资料齐全跳到 B。可以解释历史制度，但不能推出未来个人资格。

## C. 志愿建议

1. 孩子画像：届别、身份、户籍学籍/报考区、资格状态、成绩及定位口径。
2. 可报路径：区分学校类型、批次与具体专业资格，列排除项及依据。
3. 学校池：学校/专业、当届招生范围与计划、资格前提、定位理由、预算/通勤约束、官方来源。证据不足不硬分冲稳保。
4. 建议顺序：按当届批次与实际录取规则分别组织，不造通用队列，写清假设和不确定性。
5. 人工复核：资格结论、报考区、手续、当届计划、体检/加试等适用条件、填报时间与提交状态。

标记 `用户提供`、`官方已核验`、`策略判断`、`待确认`；只有确实完成网络核验时才能写“已核验”。结尾说明这是建议版，正式提交前核对官方系统和当届简章，不承诺录取。不给没有来源的精确录取概率。
